# AGENTS.md — assayd

**This file is the model-neutral source of truth for how to work on assayd.** Codex, Cursor, Copilot, Gemini and anything else that reads `AGENTS.md` starts here. `CLAUDE.md` carries the Claude-specific skill mechanics and defers to this file for everything else — so a rule lives in exactly one place and no model gets a different version of it.

assayd ("graphene" in early drafts) is a lightweight, Kubernetes-native agent platform.

**Phase: implementing P1, under the scope reset of ADR-0030.** The agent-operator, its CRD, the chart and CI exist and pass on k3d and kind.

**Do not read "approved" as "settled."** An earlier version of this line said all 27 designs were approved and critique-passed. That was false, and it was the first thing every contributor read. Design 02's own header says it "is not approved and must not be cited as such"; design 03's approves only its first slice, which the human approved on 2026-09-12 after thirteen critiques, and says the rest "is not approved, and must not be implemented", even though its whole body was consolidated on 2026-09-10 — a consolidated document is not an approved one. Design 16 also approves only its first slice, which the human approved on 2026-09-14 after twelve critiques, and the rest of design 16 is not approved and must not be implemented. Check the Status line of the design you are about to touch, and trust that over any summary — including this one. `docs/designs/README.md` carries the table.

**What is actually true of the system today**: an agent answers a request. `test/responder` is a real A2A responder, built and pushed by `hack/e2e.sh`, deployed by the operator from a registry digest, and asked a question through its revision Service — the thing no test here could do until 2026-09-06, when the e2e still ran `registry.k8s.io/pause` for everything. **Traffic now traverses a real gateway, on a route the OPERATOR emits.** `hack/e2e.sh` installs Gateway API v1.6.0 and agentgateway 1.5.0 on k3d and installs the chart with `gateway.enabled=true`; `TestAnAgentAnswersThroughTheGateway` creates an Agent, waits for the `HTTPRoute` the operator wrote to be published, and gets the agent's answer through the Gateway's own Service, with an API key. Nothing in that test authors a route any more. Deleting the route brings a new one back with a different UID, still carrying traffic; making the emitter a no-op, or rendering `--gateway-enabled=false` into the chart regardless of the value, kills both gateway e2es at the route wait. Getting there closed two gaps that were invisible from either side alone: the operator passed A5.9's admission policy and was then refused by RBAC that granted no `httproutes`, and the policy itself compared a route's `parentRef` against the *operator's* namespace rather than the *Gateway's*, so moving the Gateway made the reservation match nothing and silently admit any author (design 07 A6, A6.10).

**What remains untrue**: the chart ships no Gateway, so the e2e's Gateway is still created by the harness — and **the policy compiler is one slice deep**. With `gateway.enabled`, the operator now runs design 03's first-slice `Create` (design 03 A71, answering an independent review). A new Agent whose `-auth` compiles to API keys — which is every Agent with no `expose` block — gets `<agent>-auth` written onto a prepared route with no `backendRefs`, converged by §3.3.2's tuple, and the route is published only after an anonymous request through `--gateway-serving-url` gets `401`. `auth: none` is published at once with the marker label `assayd.dev/auth: "none"`. `oauth` and a stored `spec.budget` are `PolicyCompileFailed`, and a served Agent keeps its last good `-auth` (I1). That is ALL it enforces: no `AgentgatewayBackend` is emitted, so no budget, rate limit or tool allowlist is enforced anywhere. Since slice PR 5 (design 03 A72), a served `auth: none` Agent edited to `apikey` is locked in place by J2's `Lock`. `<agent>-auth` is written onto the route that is already serving, the route keeps its `backendRefs` throughout, and status records `apikey` only after an anonymous request through the route goes `200` → `401` and the `401` can be attributed to the policy — and **that attribution had a hole, which design 03 A77 closes**: when a promotion moved the route's `backendRef` in the crediting pass, the previous revision's own `401` was credited against the new revision's card digest, measured against `main` `3f37c25` for J2 and K2 and not reachable for the missing-policy `Lock`, which wrote no route (`docs/research/auth-lock-false-credit-2026-09.md`). **No `Lock` now takes a `ProbingAfter` answer until the Gateway reports `Accepted` and `ResolvedRefs` on the route at its current generation** — the pass that moves a route ends short of the request, still at `ProbingAfter`, and the next one probes. J2's and K2's one `ProbingBefore` request is not gated, and is not a hole: it sets `beforeObserved` only on a body whose digest equals the one `status.cards[]` records for the revision the route's single `backendRef` names, so a card from the backend the route has just left does not set it, except where two revisions serve byte-identical cards, which is the residue §3.3.3 already states (A62, A78) — **and the missing-policy `Lock` re-points its route at `status.activeRevision`**, at `ProbingAfter`, only while `status.cards[]` records a digest for that revision, so the wedge that Agent used to sit in ends when a carded revision is promoted. A route not carrying exactly one `backendRef` is unattributable. The gate is a control-plane fact, so it narrows the window rather than closing it: the proxy may still lag the controller's report, and the route is read through the manager's cache. Since design 03 A75 (ADR-0034 Amendment 5, the human's L1 and W1), no `Create` or `Lock` credits a `401` while a policy on the assayd Gateway could have answered it, or while the Gateway admits ListenerSets or cannot be read: the transaction holds at `ProbingAfter`, reason `GatewayAuthPolicy`, and pages. Re-creations of served Agents hold too, a cost the human accepted. A Gateway-level `Allow` rule was measured widening a route beside its `<agent>-auth`, so a served API-key Agent beside any counting Gateway-level policy but one that sets authentication alone reads `GovernanceSkipped=True` and `PolicyApplyIncomplete=True`, reason `GatewayAuthPolicy`, and is `Degraded`, because it cannot be ruled out that the policy widens or bypasses the route's authentication; its route is not withdrawn. The lock is one-way: `apikey` → `none` is refused. A route published before the compiler, or one whose status was lost, is refused as `Adopt` and stays unauthenticated under `GovernanceSkipped=CompilerUpgradeUnsupported`, until the Agent is deleted and created again, or K2 locks it the same way. K2 needs a stored `refusedMode` that is not `apikey` and a spec that compiles (`k2Consent`, `desire.compiles()`), and `refuseAdopt` records the mode the Agent asked for, so the default Agent — which asks for `apikey` — is not locked by editing it to `apikey`: its owner edits `auth` to `none`, waits until `status.auth.transaction.refusedMode` reads `none`, then edits it to `apikey`, with no `spec.budget` stored. An unfinished `Create`, or a J2 or K2 `Lock`, whose target no longer matches the spec is abandoned, and only the policy it wrote is deleted. A NACK Event changes status only when its `involvedObject` is the Gateway and its source is agentgateway's controller. A `traffic` policy the operator did not emit on an Agent's route is reported as `ForeignTrafficPolicy`. `TestAServedNoneAgentIsLockedInPlace` measures J2 on k3d against agentgateway 1.5.0. A `Create` refuses to write to the gateway on an install whose Agent CRD predates `status.auth`, because it could not keep its record: `helm upgrade` never updates `crds/`, and the e2e harness now applies them. A served API-key Agent that loses its route or its policy, even both at once, gets them back from `status.auth`: the route prepared and published only after a new `401`, and the policy trusted only after a `401` that can be attributed, under the same A75 gate. An API-key route with `backendRefs` is never created, only updated. One window remains: a policy deleted between a pass's check and its route update leaves the route published without it until the next pass, whose outcome depends on where it finds the transaction: a `Create` still short of `Served` finds the policy missing or changed and strips the route back to prepared before writing the policy again, and a transaction already `Served` re-creates the policy by the `Lock` with the route left open. One probe proves one gateway replica and no replica count is declared, so a served API-key Agent reads `GovernanceSkipped=False`, reason `AuthVerifiedOnOneReplica` (H2). **And a served Agent no longer reports `Ready=True` after the assayd Gateway stops accepting its route.** That defect was measured on k3d on 2026-09-14 by renaming the Gateway's listener: once no transaction was in flight nothing re-read route status, and the state never healed, because the route's `sectionName` is a constant the operator re-asserts. Design 03 A80 specified the re-derivation, the human decided its three calls on 2026-09-21, and **A81 implements it** (`internal/controller/authserved.go`). A pass of a served Agent with no transaction in the slot, or with a refused `Adopt` in it, judges two objects it has already read. An explicit `Accepted=False` or `ResolvedRefs=False` from the assayd Gateway **at the route's current generation** raises `PolicyApplyIncomplete=ServingRouteNotAccepted`, `Ready=False`, phase `Degraded`, leaves `GovernanceSkipped` where it was with a note, and **withdraws no traffic**. A served `<agent>-auth` that exists, carries the Agent's UID and renders to `appliedDigest`, whose tuple the Gateway reports broken at the policy's current generation, raises `PolicyApplyIncomplete` and `GovernanceSkipped=True`, both `AuthPolicyNotAttached` — the fail-open half, announced and not closed. **Anything that is not an explicit failure at the current generation is unknown: it raises nothing and clears nothing**, and a standing report is re-asserted from a two-flag claim store on `status.auth`, because every route write bumps the generation and the Gateway's report lags it, so the stronger rule would flip a served Agent to `Degraded` on every rollout and the obvious clearing rule would retract a true report there. **(A4-spec) was offered and not taken**, so the judgement reads no listeners and a Gateway that is readable but has stopped writing status is caught by nothing, for any mode. The operator does read `spec.listeners`, on every served pass with a mode — `capturingListeners`, for A75's W1, to decide which listener a Gateway-level policy can take traffic on — and **this judgement does not use it**; an earlier version of this paragraph said nothing reads them, which is rule 7 (A81). **The policy half is still not measured**: §8.1 case 19 (f) writes the report agentgateway would write and measures the operator's reaction to it, and the `make conformance-cluster` case that would measure the state itself is owed. **Nothing pages**, because design 10 is not built and no alert rule ships in this repository. Building it corrected two of A80's own statements: `refuseAdopt` had to carry the claim store across its wholesale assignment of `status.auth`, or the refused `Adopt` class hot-loops; and A80's one-line `authKept` remedy reaches only the passes that call `persistStatus`, which a served Agent in steady state never does. **And A81's own first implementation shipped a fatal bug its review caught**: a held report's message was appended to rather than rebuilt, so it grew a few hundred bytes a pass until the API server refused every status write for that Agent — the operator's whole status frozen during the incident the judgement exists to report, and reproduced independently by the review. A held message is now cut at its note's stable marker and rebuilt; §3.3.3 asks only that it keep its `LastTransitionTime` and `ObservedGeneration`. The operator fetches, validates and digests the card the container serves (A68), but does **not** verify its signature, cross-check its skills against the CR's grants, or count the registration deadline — §5 carries those three individually. So the platform's central claim — that governance becomes real **at the gateway** — now has its *path* proven, one *concern* compiled and enforced, and the rest of its *governance* still unbuilt.

**The gateway is now provably the only way in — under a hand-authored rule, on k3d only.** `TestTheGatewayIsTheOnlyWayIn` applies design 07 A5.4's ingress half by hand, then measures ADR-0030's stop criterion for the slice: the gateway reaches the agent, an ordinary namespace does not, and the operator's card fetch still gets through. Three mutations kill it (drop either allow rule; apply no policy). It **skips, reporting the axis unverified, on any CNI that does not enforce NetworkPolicy** — kind's default does not, and a policy there is accepted and does nothing. The operator still materializes no NetworkPolicy and holds no `networkpolicies` RBAC (design 07 A6.6).

**And it refuses a principal — under the operator's own policy.** `TestTheGatewayRefusesADisallowedPrincipal` measures the `<agent>-auth` the OPERATOR emitted — API-key authentication over a ConfigMap of `sha256:` hashes, and one CEL authorization rule admitting the group named for the Agent's namespace — at the gateway rather than at the network: permitted principal `200` with the agent's own answer, **valid credential in the wrong group `403`**, no credential `401`. The shape was measured by hand first: inverting the rule inverted both outcomes, and removing `authorization` while keeping authentication left anonymous at `401` and moved the wrong-group caller to `200`, so the `401` and the `403` are different controls and not one. The hand-authored `assayd-e2e-authz` is gone: beside the emitted policy it would be a second `traffic` policy on one route, and two resolve at random. The key set carries the product's constant label, `assayd.dev/api-keys: "true"`, and is written by an administrator; nothing in assayd writes keys. In a run namespace, admission refuses a create, or an update that changes what is reserved, of a policy from anyone but the operator and `admission.extraOperators`, and of an API-key `ConfigMap` from anyone but those and `admission.apiKeyWriters` (by default `system:masters`). Deletes are RBAC's (design 07 A6.7, A6.10; design 03 A70, A71).

**And an MCP tool call goes through it.** `TestAnAgentCallsAnMCPToolThroughTheGateway` runs a real MCP exchange — `initialize`, `tools/list`, `tools/call` — against `test/mcpserver`, a two-tool Streamable HTTP server behind an `AgentgatewayBackend` on a second Gateway listener. Its route is written by the chart's `admission.toolRouteWriters` identity, which `assayd-gateway-routes` admits on any listener but the serving one, `http`, and only with hostnames no Agent's serving host can match. Until design 07 A6.15 the e2e impersonated the operator to write it, because no one else could, so no real user could publish a tool. A hand-authored `backend.mcp.authorization` allowlist (design 03's `toolAllowlist`) does more than refuse: it **removes the disallowed tool from `tools/list`**, so an agent never learns it exists, and a refused call returns `Unknown tool` rather than "forbidden" — good for non-disclosure, a trap for whoever debugs it. Flipping the rule inverts the listing and both calls. **And an agent completes an A2A task by making the MCP call itself.** `test/responder` implements `SendMessage` on the HTTP+JSON binding its card declares. `TestAnAgentCompletesATaskByCallingAToolThroughTheGateway` sends one `SendMessageRequest` through the operator's route, with an API key, and the agent completes it by calling an MCP tool through the gateway, at the `ASSAYD_GATEWAY_URL` the operator injected. Once the gateway's allowlist excludes the tool, the same task fails with the gateway's `Unknown tool`. So ADR-0030's "one **agent** completes one A2A task and one MCP tool call through the gateway" holds — **by fixtures**. It is ONE A2A method, A2A 1.0 only, on a test fixture, and the operator speaks no A2A. The tool call is unauthenticated, and nothing restricts an agent's egress to the gateway: the fixture simply has no other address (design 07 A6.12, A6.13). The next work is the rest of the narrow slice in ADR-0030, not the next design.

## If you are here to review

You are most likely a second opinion, deliberately from a different model. That is the point: a fresh reviewer of the *same* model found three blockers in code that had passed five rounds with a previous one, including an authorization bypass. A different model should be more orthogonal still.

Read `docs/architecture.md` (canonical), the design under review in `docs/designs/`, its ADRs, and prior reviews in `docs/designs/reviews/`. Then apply the rules below. Write findings as `BLOCKER` / `MAJOR` / `MINOR` with `file:line`, a concrete failure scenario, and a specific fix — then a verdict of `PASS` or `REVISE`.

**Disagreement with another model's review is signal, not noise.** Say so explicitly and argue it; do not defer.

Several agents run at once and can reach each other through `herdr`. Read **`docs/agent-protocol.md`** before messaging one: the channels are deliberately narrow, because two agents that talk freely converge, and a consensus reached between models is worth less than the disagreement it replaced. The short version — findings are files, clarification is a message, reviewers never reconcile with each other, and nobody asks a peer what they could determine by running something.

## The rules this project learned the hard way

These are not style preferences. Each one is here because it was violated and something broke.

1. **Mutation-check every assertion.** Delete the rule a test claims to enforce; confirm the test fails. **Nine tests in this repo passed with their subject deleted** — that is the default outcome, not bad luck. A test asserting a *value* is usually weaker than one asserting a *transition*.
2. **Restore mutations from a backup copy** (`cp file file.bak`), **never `git checkout`** — it discards uncommitted work in the same file. This has cost real work.
3. **A mutation that does not compile proves nothing.** A build failure emits no `FAIL` line, so a naive runner reports "survived" for code that never built. Distinguish INVALID from SURVIVED.
4. **Self-review has never once caught what the independent pass caught.** Five rounds with one critic still left three blockers that a *fresh* critic found immediately — including an authorization bypass. Independence beats effort. Spawn a new critic when the current one nears its context limit.
5. **Defensive code no test can pin is a liability.** It reads as load-bearing and invites the next reader to trust it. Either pin it or delete it.
6. **Derivative comparison has a shape-specific hole.** apimachinery's `DeepDerivative` skips zero values for Slice, String, Map and Ptr kinds only. Drift hides in the **unset** fields of those kinds — injected `initContainers`, `Command`, capability lists. Own the fields, then compare exactly.
7. **Never state a bound the code does not enforce.** A flag's help text, a values file comment, a design table — each has shipped a promise nothing implemented. If it is not enforced, say so.
8. **Degraded paths are never silent** (NFR-8), and never *loud and wrong*: a condition must name the real cause, not a plausible one that was never checked.

## Doctrine and charter — these gate every change

- **Lightweight doctrine** (architecture §01): bind don't build · Postgres+NATS only · library over server · the reconcile loop is the product · ≤8 core pods (CI-enforced) · tiered install.
- **Pattern charter** (architecture §15): name the plane (slow=engine / fast=technique) and the socket. Five primitives only — Agent(A2A), Tool(MCP), Event(CloudEvents), Resource(CRD), Artifact(OCI). A sixth primitive or an engine change needs an RFC.
- **`docs/architecture.md` is canonical**; `docs/decisions/` holds the ADRs. Do not relitigate an ADR casually — propose a superseding one.
- **Code that diverges from an approved design is drift**, whatever it does. Amend the design first, as a numbered amendment, in the same change.

## Commands

```bash
make test          # fmt, vet, unit, envtest, chart — the pre-commit gate
make race          # anything touching shared state
make verify        # generated files are reproducible AND committed
make e2e           # k3d: create, build, load, helm install, test
DISTRO=kind make e2e
```

**Test layers, and what each can honestly claim.** unit (`api/`, `internal/`) asserts against the *generated* artifact, never a fixture in the test file. envtest (`test/envtest/`) runs a real API server but **no kubelet**, so every availability assertion there is against a status the test itself wrote. e2e (`test/e2e/`) is the only layer that can claim a pod actually runs.

**On Colima, raise `fs.inotify.max_user_instances` before debugging a broken local cluster** — see `docs/supply-chain.md`. The default starves k3s and presents as something else entirely.

## Conventions

- Commits explain *why*, and state what is not done. Conventional prefixes for docs (`docs(designs):`).
- "assayd" is a codename (ADR-0001). Flag it before it reaches anything expensive to change — API groups, module paths.
- **The user decides, with reasoning shown.** Present options with trade-offs and a recommendation; never a silent choice, never a blank menu.
