# Identity facts for design 06 (2026-08)

- **Zitadel RFC 8693**: native token exchange from v2.49+ — impersonation & delegation; audience-narrowing rule: exchanged tokens may never gain audiences absent from subject/actor inputs. Full management API (orgs, projects, clients, machine users/keys); declarative machine-key init supported by the chart. https://zitadel.com/docs/guides/integrate/token-exchange
- **agentgateway token exchange is OSS** (r1-f1 verdict): open-sourced in the release following 2.2 (PRs #2189 data plane, #2458 k8s controller) — `oauthTokenExchange` on AgentgatewayPolicy/Backends with `audiences`, `scopes`, `actorToken` (RFC 8693 `act` delegation), `resources`, `cache`, `subjectToken.source`; IdP-agnostic (Keycloak, Okta, Zitadel named). Chart must pin ≥ that version. Solo *Enterprise* docs describe adjacent MCP-token-exchange conveniences — not required. https://agentgateway.dev/blog/2026-07-12-agentgateway-token-exchange-jwt-assertion-entra-obo/ · enterprise-tiered adjacents: https://docs.solo.io/agentgateway/latest/security/token-exchange/
- **Keycloak profile**: token exchange is a non-default feature (feature flag; standard token-exchange support matured through 2025-26 releases) — the profile must enable + pin it and conformance must assert it.
