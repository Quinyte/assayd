# llm-d / KServe generative serving — facts for design 25 (2026-08-22)

Supersedes the `landscape-2026-08.md` §Modelhub line "llm-d for single-giant-LLM high-throughput",
which is stale in a way that mattered: **KServe's generative path is built on llm-d**, so binding
KServe for LLM serving binds llm-d transitively whether the design says so or not.

- **llm-d → CNCF Sandbox** (donated 2026-03-24; IBM, Red Hat, Google, CoreWeave, NVIDIA). Kubernetes-native by construction — standard CRDs, Gateway API, standard networking (explicitly unlike NVIDIA Dynamo). https://github.com/llm-d/llm-d · https://llm-d.ai/blog/llm-d-announce
- **Capabilities**: disaggregated prefill/decode (compute-bound prefill and bandwidth-bound decode scheduled separately, removing head-of-line blocking), KV-cache-aware / prefix-aware routing, tiered KV offloading, wide expert parallelism, **scale-to-zero autoscaling** (v0.5), active-active HA. v0.6.0 (2026-04-03) adds inference-scheduler v0.7.1 with a scorer plugin ecosystem and AMD ROCm / Intel Gaudi / CPU-AMX accelerators.
- **KServe v0.17 (2026-03-13)** promoted **`LLMInferenceService`** to production-ready — **built on llm-d** — and split KServe into three components: `kserve` (core, `InferenceService`), `llmisvc` (the LLM controller), `localmodel` (optional caching). `InferenceService` remains the classic/predictive path. https://kserve.github.io/website/blog/kserve-0.17-release · https://kserve.github.io/website/docs/model-serving/generative-inference/llmisvc/llmisvc-overview
- **The seam is GAIE** (`kubernetes-sigs/gateway-api-inference-extension`): the `InferencePool` API + endpoint-picker (EPP) protocol lets a gateway route to a scheduler without embedding scheduling logic. https://github.com/kubernetes-sigs/gateway-api-inference-extension
- **agentgateway speaks it, in OSS** — two modes: Kubernetes Gateway API mode (install GAIE CRDs, create an `InferencePool`, route to it from an `HTTPRoute`) and standalone request-scheduler mode (sidecar alongside the EPP over localhost). Not a Solo Enterprise feature — ADR-0020 D1 holds. https://agentgateway.dev/docs/inference/ · https://agentgateway.dev/blog/2026-03-19-agentgateway-llm-d-gaie-inference-serving/
- **Reported effect** of prefix-cache-aware routing in one deployment: ~3× output tok/s, ~2× lower TTFT.
- **Maturity caveat**: Sandbox-stage, v0.5→v0.6 in ~2 months. P5 is the last phase, so this *will* move again before implementation — bind the **contracts** (`LLMInferenceService`, `InferencePool`), never llm-d internals.
