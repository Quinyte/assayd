# Diagram audit — 2026-09-22

An audit of the eight plates in `docs/diagrams/` against the code, the chart, and the Status
line of each design they cite; and a proposed diagram set for the public website's concepts
section.

**This document changes nothing.** It does not edit the plates, `docs/diagrams/README.md`, or
`docs/diagrams/prompts.md`. Where it recommends a change, another pass makes it.

**Revised 2026-09-23 against `main` at `c4e5020`.** Since the audit ran, PR #57 built the website
scaffold under `web/` — including the `ClaimClass` badge and the `Figure` component every plate will
be placed with — PR #59 generated `docs/reference/conditions.md`, PR #60 merged the docs honesty gate,
and design 03 A82–A84 and design 02 A77 changed two subjects this audit proposes to draw. The
revision: **P6** is redrawn on A82's measurement, A83's message and A84's decision; **P8** is redrawn
on A77's recorded UID; **P7**'s collision reasons are split; **P12** loses a tick that dated an
implementation that does not exist; **the legend** is reconciled with `web/shared` rather than
specified beside it; **X-4**, **DOC-2**, **DOC-3** and *What this audit could not check* are
brought up to date; plates **06** and **08** are given an explicit fate; and every citation names a
symbol, a section or a heading instead of a line number, because the line numbers had already
drifted. The verdicts in Job 1 are unchanged. **A second pass the same day, against `main` at
`9a74178`**, answered an independent confirmation: P8 now says provenance adopts (not only the
vouched ground), P6's *unknown × broken* cell is split on a standing route claim and names A82's two
caveats, the legend no longer calls a `figcaption` one block, three prompt sketches lose strokes the
legend does not define, and DOC-2 records PR #66's correction of twenty-three Status lines, not
eight.

**Decisions by the human that bind this audit**: every diagram is a generated `.webp` — **no
Mermaid anywhere**; the site uses the system font stack and no webfont; a security gap is named and
linked, never given with a reproduction recipe; and a design's own Status line is the source of truth
for its state, with `docs/designs/README.md` summarising it (2026-09-23; see DOC-2).

**Why this audit exists.** The eight plates were generated on 2026-08-20 and 2026-09-10 — before
ADR-0030's scope reset and before the policy-compiler slices landed. They are candidates for a
public site. `CLAUDE.md` opens with the lesson that a false summary is worst when it is the first
thing every reader sees; a false plate on a public site is that mistake at larger reach and with
no Status line beside it to correct it.

## Method, and what "verified" means here

Each plate was **opened as an image and read element by element** — every box, every edge label,
every caption — and each element was then checked against the repository. The README table was
treated as a description of intent, not as evidence, and was itself audited. Where a claim could
not be checked, it is marked unchecked rather than guessed.

Pixel colours were sampled programmatically from the `.webp` embed copies rather than judged by
eye. Image metadata was read by parsing PNG chunk headers and the WebP RIFF container directly,
because `exiftool` is not installed on the machine this audit ran on.

### Claim classes

Every element below is assigned one of three classes. A plate that mixes classes **without marking
them** is itself a finding, and is recorded as one.

| Class | Meaning |
|---|---|
| **measured** | A named test in this repository proves it. The test is cited. |
| **designed** | A design doc or `docs/architecture.md` specifies it. Nothing in the code enforces it. |
| **not-built** | No implementing code. In several cases also no approved design. |

### Verdicts

| Verdict | Meaning |
|---|---|
| **KEEP** | Publishable as-is, or with a caption change only. |
| **RE-DERIVE** | The subject is worth a plate; this rendering asserts something false and must be redrawn from the code. |
| **KILL** | The subject should not appear on a public site at all in its current state. |

## Design system — the binding constraints

Restated from the visualizer plugin's shared design-system file — `backlot/visualizer` 0.1.0,
`shared/design/design-system.md` — read in full for this audit. The plugin and version are named so
these findings are auditable; the absolute path is a local plugin cache and is deliberately not
recorded.

- **Ground** — warm off-white `#FAFAF7`. `#0F0F12` ink-dark only for hero / full-bleed editorial.
- **Ink** `#14141A` — the workhorse: headings, body text, linework, primary marks.
- **Gold** `#C8A24B` — **exactly one decorative beat per composition.** Never on an interactive
  element. Never paired with `error` red.
- **`gold-light` `#E7D8AE`** — text at 16px or smaller only; prefer it as a tint fill.
  **`gold-tint` `#F3ECD9`** — band and section washes, outline-variant.
- **Typography** — geometric sans, Inter-like. **Headings stay at weight 400**; weight 500 only on
  small labels. For image prompts, request "geometric sans-serif similar to Inter, weight 400,
  slightly editorial, generous tracking on display sizes". Never name Helvetica, Arial, Sora,
  Advocate, or Concourse.
- **No shadows. No gradients** — at most one subtle ink→ink-dark wash on a hero surface.
- **No purple**, and no `#EA4335` / `#9AA0A6` Slides leakage.
- **No watermark** — no wordmark, signature or logo glyph in any prompt. Branding is opt-in
  per-invocation only.

### Measured conformance of the existing set

Modal background colour, sampled from the **`.png` masters** — the `.webp` embeds are a lossy
re-encode and shift channels by a unit or two, which is enough to reverse a channel comparison, so
they must not be used for this measurement. Deltas are against the spec ground `#FAFAF7`.

| Plate | Ground measured | ΔR | ΔG | ΔB | Gold measured (from the `.webp`) |
|---|---|---|---|---|---|
| 01 | `#F4E9D5` — this is the **band wash**, which covers most of the canvas; not the ground | −6 | −17 | −34 | `#C2A45F` |
| 02 | `#F8F7F3` | −2 | −3 | −4 | `#C7A34D` |
| 03 | `#F8F7F3` | −2 | −3 | −4 | `#CEA54F` |
| 04 | `#F8F7F3` | −2 | −3 | −4 | `#C5A051` |
| 05 | `#F8F7F3` | −2 | −3 | −4 | `#CDA857` |
| 06 | `#F9FAF5` | −1 | **+0** | −2 | `#C5A04F` |
| 07 | `#FCFBF9` | +2 | +1 | +2 | `#C4A557` |
| 08 | `#F6F5F1` | −4 | −5 | −6 | `#CAA554` |

**Finding — DS-1 (MAJOR, and narrower than it first looked).** **No plate lands on the specified
ground.** Six of the seven measurable grounds (01's row measures a wash, not a ground, and is not
evidence for this finding) hold the spec's warm ordering R > G > B and miss it by two to six units
per channel; plate 06 alone inverts R and G, **by one unit**, which is a rounding artifact and not
a visible cast. Gold drifts by up to 12 in a channel, which is the larger deviation.

**An earlier draft of this finding claimed plates 02, 04 and 06 were "green-cast". That was wrong,
and it was wrong because it was measured from the `.webp` derivatives rather than the masters** —
the re-encode moved G above R by a single unit in two of them. Recorded here rather than quietly
corrected, because it is the same class of error this audit charges the plates with: a confident
claim from a convenient source instead of the authoritative one.

What survives is the point that matters: an image model does not honour an exact hex, so brand
colour cannot be *asserted* through generation, only *approximated* and then checked. A site that
places these plates beside HTML painted with the literal tokens will show a seam. That is an
argument for measuring every generated plate on arrival — not for the provenance mechanism in Job 2,
which addresses a different failure.

**Finding — DS-2 (MAJOR).** **Plate 01 is set in a monospace face.** Every string in it — the title
and all fourteen labels — has uniform character advance. The design system requires geometric sans.
Plate 01 and plate 07 were re-rendered on the same day (`docs/diagrams/README.md`, the line
beginning "Plates `01-architecture` and `07-what-runs` were re-rendered on 2026-09-10"), and 07 is
correctly set in geometric sans — so the set is internally inconsistent as well as off-spec.

**Finding — DS-3 (MINOR).** **Headings are bold on plates 01, 03, 06 and 08**, against the explicit
rule "Headlines stay at weight 400. Bold display headings read as shouting." Plates 02, 04, 05 and
07 hold the rule. Half the set breaks it.

**Finding — DS-4 (MINOR).** **Plate 03's gold beat is two elements**, not one — the `exchange RFC
8693` arrow and the `agent-scoped token` arrow are both rendered as thick gold. `prompts.md` names
the beat as "the exchange arrow pair", which concedes the point. Defensible as one *idea*; it is
not one *element*, which is what the rule says.

2. The `hf-job-id` UUIDs are **generation-service job identifiers**, which `prompts.md`'s opening

library, need no dependency, and should run in CI over `docs/diagrams/` so a future regeneration
cannot quietly reintroduce a metadata block. Specified as part of the drift mechanism below.

# Job 2 — the diagram set the website needs

## The lane decision, and what it costs

**One lane. Every plate is a generated image delivered as `.webp`.** Mermaid and `drawio-architect`
are out by decision; the question per concept is *which image skill*, not *which lane*. The
available skills are `visualize` (orchestrator), `technical-diagram`, `isometric`, `framework`,
`concept-map`, `timeline`, `taxonomy`, `comparison`.

The `visualize` orchestrator was run over the concepts list and its routing table applied per
concept; each selection below carries the orchestrator's reasoning, not just its name.

**Where the orchestrator's routing and the one-lane decision disagree, and how it was resolved.**
The orchestrator routes "flowchart, sequence, state, class, ER" to `mermaid` — which is exactly the
shape of five of the eight requested concepts (P3, P5, P6, P7, P10). With `mermaid` removed, those
five route to their nearest available neighbour, `technical-diagram` ("freeform boxes-arrows-labels
engineering diagram"), which draws the same content without the grammar. **This is a real loss and
it is recorded, not papered over:** a state machine drawn as a freeform diagram has no parser to
reject a missing state, so the correctness burden moves entirely onto the prompt, the text
alternative, and the review. The two mitigations below exist because of it.

### Cost 1 — a generated image cannot be diffed against code

Mermaid source could have been CI-checked against the enum it draws. A `.webp` cannot. Drift
protection has to come from elsewhere.

**An earlier version of this section proposed a parallel `docs/diagrams/provenance.yaml`**, one
record per plate carrying `depicts_commit`, `claim_class`, `proven_by`, `sources_of_truth` and an
alt-text file. **Withdrawn: PR #57 built the mechanism into the component instead**, and a second
record beside it would be two holders of one fact. `web/shared/src/components/Figure.astro` — the
component every plate is placed with — takes:

| `Figure` prop | What it carries | Replaces |
|---|---|---|
| `depicts` | "The version, tag or commit whose behaviour this plate depicts", rendered in the caption as *depicts `<rev>`*. The component's own comment calls it "the staleness stamp". | `depicts_commit` |
| `claim` | One `ClaimClass` claim — `measured` with its `test`, `designed` with its `design` and `section`, or `not-built` — rendered as the badge in the caption. `web/scripts/check-claims.sh` resolves the test or design against the repository in the built HTML. | `claim_class` and `proven_by` |
| `alt` | The text alternative. **Required**: the build fails on an empty one or on one that is the file's own name. | `alt_text_file` |

**What this costs, and what is proposed for it.**

1. **`depicts` and `claim` are optional props.** Nothing fails a plate that carries neither. The
   rule for this set is that every plate carries both; **enforcing it is owed** to `web/`, and the
   natural home is a build-time throw in `Figure` of the kind it already has for `alt`.
2. **A `depicts` stamp alone cannot go red when the code moves.** The withdrawn record carried
   `sources_of_truth`, and a CI job diffed `<depicts_commit>..HEAD` against them. That check has no
   input now. **Proposed**: keep each plate's source-of-truth list in its section of
   `docs/diagrams/prompts.md` — which already holds the plate's prompt and is already the file a
   regeneration reads — and have the check read the stamp from the page and the list from the
   prompt. **Not built.** It surfaces a change in a diff; it does not guarantee one is caught, it
   watches only the files someone listed, and its remedy — bumping the stamp — clears it whether or
   not anyone looked, so a bump must say in its commit what was re-read. **And `actions/checkout`
   must be deepened** (`fetch-depth: 0`), because every checkout in `.github/workflows/` is shallow,
   under which `git diff <rev>..HEAD` fails `fatal: bad object`.
3. **One claim per figure** is a hard rule of the component's check, not a style choice:
   `Figure` takes a single `claim` prop, so it renders at most one badge. (`block_scope.py` is not
   what enforces this for a figure: it keys each badge by its nearest block, and `Figure` renders
   the badge in `<p class="fig__stamp">` and the caption text in `<div class="fig__text">` — two
   blocks. **A note for `web/`: a figure's caption and its badge are not one block**, so a
   retraction in the caption text does not share a rescue scope with the badge.) So a plate whose
   elements span classes gets **one** figure-level
   claim, and its per-element classes are carried by the artwork's strokes — see *The legend the
   site needs*, which says how each mixed plate maps.

The same CI job should carry the **metadata assertion** from the EXIF section: parse each plate the
site **serves** — every `.webp` under `web/*/public/` — and fail on any
`tEXt`/`iTXt`/`zTXt`/`eXIf` or `EXIF`/`XMP `/`ICCP` chunk. Pure standard library; no `exiftool`
dependency. **Scoping it to what ships is not incidental** — all eight existing PNG masters under
`docs/diagrams/` carry an `hf-job-id` `tEXt` chunk, and the verdicts above withdraw those plates from
the *site*, not from the repository, so a check over `docs/diagrams/*.png` would be red from its
first commit. **Not built.**

This matters most for the two plates whose subjects change under them fastest — **P3 (the auth
transaction)** and **P5 (the attribution gate)**. Both sit on `internal/controller/authtxn.go`,
which design 03's amendment stream has rewritten repeatedly (A75, A77, A80, A81 in three weeks).
Both should be regenerated as a matter of course whenever that file changes, not merely flagged.

**A fourth part, recommended and cheaper than all three:** put the **claim-class marker inside the
artwork**. A plate that carries the word *designed* in its own pixels stays honest when it is
screenshotted, reposted, or read after its caption is lost. See the legend note at the end.

### Cost 2 — an image is invisible to a screen reader and to search

Each plate below carries a **text alternative**: prose that conveys the same information, which for
a state machine means naming the states and the transitions in words. `Figure` requires an `alt`,
and the build fails without one; but the drafts below are longer than an `alt` attribute should be,
so the proposal is that each plate's full text alternative is **page content, rendered in the
page body beside the figure**, and its `alt` is a one-sentence summary of what the plate shows.
Writing them after the images is how they end up useless, so each is drafted here.

### P3 · The auth transaction and its stages

**This plate must not be drawn from the brief's stage list.** The brief gave
`PreparingRoute → ApplyingPolicies → Converging → ProbingAfter → Publishing → Served`. Checked
against the code, that list is **wrong in two ways**, and the plate has to be drawn from the
constants:

The `Stage*` constants in `internal/controller/authtxn.go` define seven stages:
`Refused`, **`ProbingBefore`**, `PreparingRoute`, `ApplyingPolicies`, `Converging`, `ProbingAfter`,
`Publishing`.

1. **`ProbingBefore` is missing from the brief's list and is load-bearing** — it is where a `Lock`
   takes its single before-answer, and `BeforeObserved` (`api/v1alpha1/agent_types.go`, the
   `BeforeObserved` field) exists only to record its result.
2. **`Served` is not a stage.** There is no `StageServed` constant; the string "Served" appears in
   Go only as a test-table label in `TestGoldenTheEmittedAuthNoneRoute`
   (`internal/controller/authnone_golden_test.go`). The highest stage written is `StagePublishing`
   (in `authStep` and `runCreate`). **"Served" is the condition that
   `status.auth.mode` is recorded *and the transaction slot is empty*** — which is exactly how the
   code tests for it, in `reportAboveServed`: `if !r.Gateway.Enabled || auth == nil || auth.Mode == "" ||
   auth.Transaction != nil`. The comment on `routePublicationFor` confirms the sequencing: a `Create` at
   `Publishing` writes the route "before `status.auth` records the mode at `Served`".

   **So `Served` must be drawn as the transaction slot emptying, not as a seventh box.** That is
   literally how it is written: `servedRecord` (`authtxn.go`) returns a fresh
   `AuthStatus` carrying `Mode`, `KeySource`, `AdmittedGroups`, `AppliedDigest` and `Verified` and
   **no `Transaction`**, and `recordServed` assigns it wholesale.

   **This is a difference of abstraction level, not a defect in the design.** Design 03 — whose
   first slice is the approved one — names `Served` as the terminal member of the chain in §1.1
   itself (`docs/designs/03-policy-compiler.md` §1.1, and again for `Lock` in §1.1 and §3.3.3), and
   it is right to: `Served` is the transaction's terminal *outcome*, and the code records that
   outcome by emptying the slot rather than by writing a seventh stage value. **The plate must draw
   the design's `Served`, in the code's shape.** The one thing worth correcting is the CRD field
   comment on `AuthTransaction.Stage` in `api/v1alpha1/agent_types.go`, which lists `Served` among the values of
   `status.auth.transaction.stage` — where it can never appear. **Recommended to the docs pass as a
   wording change, not fixed here, and not a finding against design 03.**

3. **The chain is not linear, and the plate must not draw it as one.** Each entry point starts at a
   different stage: a `Create` for `auth: none` **skips straight to `Publishing`**
   (`authStep`); a `Create` for `apikey` starts at `PreparingRoute` (also `authStep`); J2 and
   K2 Locks start at `ProbingBefore` (`enterLock`); the missing-policy Lock starts at
   `ApplyingPolicies` with `Written: true` (`lockMissingPolicy`); an `Adopt` only ever sits at
   `Refused` (`refuseAdopt`). **No `Lock` of any flavour passes through `Publishing`** — design 03
   §1.1 and §3.3.3 give the Lock chain as `ProbingBefore` (J2 only) → `ApplyingPolicies` → `Converging` →
   `ProbingAfter` → `Served`, because a Lock's route is already serving and has nothing to publish.

- **Skill: `technical-diagram`.** Routes to `mermaid` (state diagram) under the orchestrator;
  `mermaid` is out, so `technical-diagram` draws the states as boxes and the transitions as labelled
  arrows. `framework` was rejected — this is a sequence with guards, not a mental model.
- **Claim class: mixed, and this one needs care.** Individual stages are asserted as string
  literals across the envtest suite (`test/envtest/authcreate_test.go`, `authlock_test.go`,
  `authrace_test.go`, `authrecreate_test.go`), and the J2 lock is **measured** end-to-end by

  `Stage` carries no `+kubebuilder:validation:Enum` (unlike `Kind`, `TargetMode`, `RefusedMode` and
  `Mode`, which all do), and `TestStatusAuthIsTheSlicesSubset` (`api/v1alpha1/schema_contract_test.go`) pins enums for
  those four and **not** for `stage`. So nothing can fail if a stage is added, renamed or dropped — which
  makes this the plate most exposed to Cost 1, and the strongest argument for the `depicts`
  stamp and its staleness check (Cost 1).
- **One sentence to leave with:** *An Agent's authentication is applied as a resumable transaction
  that publishes its route only after an anonymous request has actually been refused.*
- **Gold beat:** the `ProbingAfter` box — the stage where the operator waits for a real `401` rather
  than trusting its own write, which is the whole idea.
- **Sources of truth:** `internal/controller/authtxn.go`, `api/v1alpha1/agent_types.go`
  (`AuthTransaction`), `internal/controller/authabove.go`, `test/e2e/lock_test.go`.
- **Prompt sketch:** Left-to-right chain of six ink boxes on off-white, geometric sans weight 400,
  flat: `PreparingRoute` → `ProbingBefore` → `ApplyingPolicies` → `Converging` → gold-outlined
  `ProbingAfter` → `Publishing`, then a solid ink arrow to a box in the measured stroke — `Served` is real, it is

  recorded at `status.auth.transaction`. Its stages, as the controller defines them, are
  PreparingRoute, ProbingBefore, ApplyingPolicies, Converging, ProbingAfter, Publishing — and
  Refused, which only an Adopt ever occupies. PreparingRoute writes an HTTPRoute with no
  backendRefs. ProbingBefore is where a Lock takes its single before-answer through the route that
  is already serving. ApplyingPolicies writes the `<agent>-auth` policy; the transaction is marked

  all — it sits at Refused.*

**Redrawn 2026-09-23.** The first version of this plate drew a 2×2 of *route accepted / refused* by

- **Skill: `framework`.** The content is a matrix with a precedence rule in it; only a matrix shows

- **What the plate must now say, fact by fact:**

### P8 · Who owns the revision's objects — a recorded UID for the Service, a stamp for the workload

**Redrawn 2026-09-23.** The first version of this plate made the `assayd.dev/revision-digest`
annotation "the one stamp that is actually checked", and drew the four labels as corroboration
beneath it. **Design 02 A77 (PR #54) made that wrong for the Service**, which is the object this plate
is about: a stamp can be forged by anyone who can `create` a Service in the run namespace and
stripped by anyone who can `patch` one, and A77 measured a delete gated on it failing in both
directions. The Service's owner is now decided by a **recorded UID** first; the stamp decides only
for an object with no record; and garbage collection is the one path still decided by name. The
**workload** (the Deployment) is unchanged: it is still decided by name and stamp.

- **Skill: `technical-diagram`.** Component relationships across a namespace boundary, plus one
  decision.
- **What the plate must now say, fact by fact:**
  1. **The recorded UID decides first, for a revision Service.** `status.revisionServices` holds,
     per revision and digest, the UID the API server returned when this operator created the
     Service — or the UID of one it adopted. An object whose UID matches is the operator's own
     **whatever its labels and annotations say**; provenance is not consulted for it. Its wrong
     *shape* is converged back.
  2. **Provenance decides for any other object**, on three grounds, each refused as
     `RevisionHashCollision` under its own reason: `ForeignObject` (the `assayd.dev/agent-uid` label
     is another Agent's), `DigestMismatch` (the digest is stamped and differs), `Unstamped` (no
     stamp, and status vouches for no such revision). Refused objects are left untouched.
  3. **Provenance adopts.** Any object with no record that **passes** provenance and is not
     headless is converged to the render and its UID recorded — `adoptServiceRecord`, on both
     converge exits of `ensureService`. Two ways to pass:
     - **stamped for this revision, with this Agent's UID label → converged, recorded.** This is
       the common case: every new revision's own Service, and every Service of an Agent created
       before the record existed, is adopted this way on first sight;
     - **unstamped, at a revision status vouches for → converged, re-stamped, recorded**
       (`TestAnUnstampedServiceAtAVouchedRevisionIsAdoptedAndRestamped`).

     So the stamp is not what makes an object the operator's; the record is, and labels decide only
     whether an unrecorded object may be adopted. **What that concedes, from
     `adoptServiceRecord`'s own comment:** a revision's name is predictable from its spec, so a
     principal who can create a Service in the run namespace can place one at the next revision's
     name first, carrying labels that pass provenance, and it is adopted. The convergence makes it
     identical to the render before it is recorded, so it carries no traffic the operator's own
     would not; what the record adds is that a later headless state of it is replaced. An object
     headless on first sight is never recorded, so never deleted. Design 02 §5 states the same.
  4. **Only the record authorises a destructive replace.** A Service whose `spec.clusterIP` is
     `None` cannot be repaired by an update, so the operator deletes it with the **recorded UID as
     the delete's precondition** and recreates it — at most once per revision per ten-minute window,
     counted in `status`. An object whose UID is not recorded is never deleted
     (`RevisionServiceNotRecorded`).
  5. **New reasons the plate should name, not explain**: `RevisionServiceNotRecorded`,
     `RevisionServiceRecordNotKept`, `RevisionServiceReplaceFailed`, `RevisionServiceReplaceHeld`,
     `RevisionServiceUnreadable`, and `ActiveRevisionServiceUnaddressable` (which P6 also meets).
     Each has an entry in `docs/reference/conditions.md`; the page links there.
  6. **Garbage collection is still decided by name.** `collectRevisionServices` deletes a retired
     revision's Service chosen by `ownedServices`, whose test is the immutable name
     `<agent>-<revision>` corroborated by the Agent-UID label — no record is consulted. The same is
     true of the workload (`TestWorkloadDeletionAuthorityIsTheName`).
  7. **The workload is still decided by name and stamp**: `ensureWorkload` refuses a Deployment
     without the Agent's UID label or with a digest that differs, as before.
  8. **No ownerReference crosses the namespace boundary** — unchanged, and still the reason any of
     this is needed.
- **Claim class: measured**, envtest and unit — no kubelet, so nothing here shows traffic.
- **One sentence to leave with:** *The operator knows a revision's Service is its own because it
  recorded the UID of the Service it created or adopted; labels decide only whether an unrecorded

- **Gold beat:** the `status.revisionServices` record, and the arrow from it to the delete it

- **`proven_by`** (the figure's `claim` names the first): `TestTheReplaceDeletesTheObjectItReadAndNotTheName`,

## The legend the site needs

**The first version of this section specified a legend that contradicted the component the site
now has, and contradicted itself.** It gave `measured` a solid-gold swatch, `designed` solid grey
and `not built` dashed grey — while every plate spec above allows exactly one gold beat per
composition, so a plate with three measured elements could not draw all three in gold without
breaking the design system, and the gold beat would then mean two different things on one plate.
And PR #57 has since built the site's `ClaimClass` badge (`web/shared/src/components/ClaimClass.astro`)
**on a deliberately different vocabulary**. Its own brief: "IT IS NOT A COLOURED PILL … The three
classes are told apart by STROKE — filled, hairline, dashed — and by a mark that survives
greyscale", and "IT IS NOT GOLD. Gold is one decorative beat per composition." **This section now
follows the component, not the other way round.**

**The legend is the `ClaimClass` badge itself, not a separate strip.** There is no second legend
component to build: `/claim-classes.html` defines the three classes on the site, and every `Figure`
renders its one badge in its caption. What the artwork must do is use **the same stroke vocabulary**,
so that a reader who has learned the badge can read the plate:

| Class | Badge (built) | In the artwork |
|---|---|---|
| **measured** — a named test proves it | filled ink, mark `●` | **solid ink**, heavier stroke (the badge's header form uses 2px) |
| **designed** — specified, nothing enforces it | ink hairline outline, mark `◐` | **ink hairline**, no fill |
| **not built** — no implementing code | dashed grey outline, mark `○` | **dashed `#999999`** outline, no fill |

**Gold carries no class.** It is the plate's single decorative beat and marks *the idea the reader
should leave with*, which may be a measured element, an inert one, or a refusal. Every "gold beat"
bullet above is to be read that way; where a prompt sketch above says an element is "solid gold" to
mean it is measured — P9's solid arc was one — the element is drawn in the measured stroke, and the
gold is spent on it only if it is also the plate's one beat.

**One claim per figure — so mixed plates need an explicit mapping.** `Figure` takes a single `claim`
prop, and that, not `block_scope.py`, is what limits a figure to one badge (Cost 1, item 3). The
rule: **the figure's badge classes the plate's one sentence to leave with, and the artwork's
strokes class each element.** A plate whose sentence cannot be classed as one thing is split. For the
plates this audit marks mixed:

| Plate | Figure-level `claim` | How the rest is carried |
|---|---|---|
| **P2** — the proven path | `measured`, `TestAnAgentAnswersThroughTheGateway` | The objects assayd does not author — Gateway, listeners, tool route, `AgentgatewayBackend` — are real in the test, so they are not `not built`; they sit on a tinted zone with the plate-local label *not authored by assayd*, in the measured stroke. A class stroke would misstate them. |
| **P3** — the auth transaction | `measured`, `TestCreatePublishesOnlyOnA401` | Every stage is drawn in the measured stroke. The unpinned fact — no test fails if a stage is added, renamed or dropped — goes in the caption prose, because it is a fact about the test suite, not a class of any element. |
| **P6** — judging a served Agent | `measured`, `TestBothHalvesOnOnePassNameTheRouteFirst` | Cells in the measured stroke. The layer — envtest for the reaction, conformance-cluster for the two policy states, nothing automated for the route state — is in the caption prose. |
| **P9** — governance | `measured`, `TestTheGatewayRefusesADisallowedPrincipal` | One arc in the measured stroke; three arcs dashed grey, each labelled *not built*. The sentence claims only the one arc, which is why a `measured` badge is honest here. |
| **P12** — how the slice was proven | **none** (P12 says why) | Its own filled/open tick key, which is not the site legend. |
| **01**, **02**, **06**, **08** (the existing mixed plates) | — | Not published; Job 1's verdicts stand, and P1, P2 and P9 replace 07, 01 and 05. |

**Two rules keep it honest:**

1. **Whatever a plate draws in the measured stroke, a named test must prove, and the figure's badge
   must name one.** Each plate's `proven_by` bullet above lists its tests; the figure's `claim`
   names the one that proves the plate's sentence, and the rest belong in the caption prose. `check-claims.sh` fails a `measured` badge whose test does not exist. A draft of
   this proposal classed four plates `measured` and cited a test on none of them; the rule exists
   because that is the easy mistake.
2. **No plate may invent a fourth class.** A draft of P12 used "measured history", which the badge
   cannot render. If a distinction is worth drawing and does not fit these three, it belongs in the
   plate's own key — as P12's filled/open tick marks now do — not in the class vocabulary.

**The fate of plates 06 and 08**, which Job 1 sends back for re-derivation and which have no
replacement in the twelve:

- **`06-api-surface` is withdrawn, not owed.** Re-derived honestly it is one box: one CRD, one
  user-facing Kind. A picture of one box carries nothing a sentence does not, and the generated
  `/reference/crd-agent` page (`docs/reference/crd-agent.md`) is the API surface, held to the code by
  `make verify`. If a second Kind ships, the subject returns.
- **`08-rollout-lifecycle` is owed, and deferred.** Four real states — `Pending`, `Held`, `Ready`,
  `Degraded` — are worth a plate. It is not in the first set because design 16's approved first slice
  is exactly what would change them, and nothing it specifies is implemented yet; a plate generated
  now would be re-derived again when it lands. It is owed when that slice is implemented, drawn from
  the phases the controller sets, not from the enum (X-4).
