# Diagram audit — 2026-09-22

An audit of the eight plates in `docs/diagrams/` against the code, the chart, and the Status
line of each design they cite; and a proposed diagram set for the public website's concepts
section.

**This document changes nothing.** It does not edit the plates, `docs/diagrams/README.md`, or
`docs/diagrams/prompts.md`. Where it recommends a change, another pass makes it.

**Why this audit exists.** The eight plates were generated on 2026-08-20 and 2026-09-10 — before
ADR-0030's scope reset and before the policy-compiler slices landed. They are candidates for a
public site. `CLAUDE.md` opens with the lesson that a false summary is worst when it is the first
thing every reader sees; a false plate on a public site is that mistake at larger reach and with
no Status line beside it to correct it.

---

## Method, and what "verified" means here

Each plate was **opened as an image and read element by element** — every box, every edge label,
every caption — and each element was then checked against the repository. The README table was
treated as a description of intent, not as evidence, and was itself audited. Where a claim could
not be checked, it is marked unchecked rather than guessed.

Pixel colours were sampled programmatically from the `.webp` embed copies rather than judged by
eye. Image metadata was read by parsing PNG chunk headers and the WebP RIFF container directly,
because `exiftool` is not installed on the machine this audit ran on.

### Claim classes

Every element below is assigned one of three classes. A plate that mixes classes **without marking
them** is itself a finding, and is recorded as one.

| Class | Meaning |
|---|---|
| **measured** | A named test in this repository proves it. The test is cited. |
| **designed** | A design doc or `docs/architecture.md` specifies it. Nothing in the code enforces it. |
| **not-built** | No implementing code. In several cases also no approved design. |

### Verdicts

| Verdict | Meaning |
|---|---|
| **KEEP** | Publishable as-is, or with a caption change only. |
| **RE-DERIVE** | The subject is worth a plate; this rendering asserts something false and must be redrawn from the code. |
| **KILL** | The subject should not appear on a public site at all in its current state. |

## Design system — the binding constraints

Restated from the visualizer plugin's shared design-system file — `backlot/visualizer` 0.1.0,
`shared/design/design-system.md` — read in full for this audit. The plugin and version are named so
these findings are auditable; the absolute path is a local plugin cache and is deliberately not
recorded.

- **Ground** — warm off-white `#FAFAF7`. `#0F0F12` ink-dark only for hero / full-bleed editorial.
- **Ink** `#14141A` — the workhorse: headings, body text, linework, primary marks.
- **Gold** `#C8A24B` — **exactly one decorative beat per composition.** Never on an interactive
  element. Never paired with `error` red.
- **`gold-light` `#E7D8AE`** — text at 16px or smaller only; prefer it as a tint fill.
  **`gold-tint` `#F3ECD9`** — band and section washes, outline-variant.
- **Typography** — geometric sans, Inter-like. **Headings stay at weight 400**; weight 500 only on
  small labels. For image prompts, request "geometric sans-serif similar to Inter, weight 400,
  slightly editorial, generous tracking on display sizes". Never name Helvetica, Arial, Sora,
  Advocate, or Concourse.
- **No shadows. No gradients** — at most one subtle ink→ink-dark wash on a hero surface.
- **No purple**, and no `#EA4335` / `#9AA0A6` Slides leakage.
- **No watermark** — no wordmark, signature or logo glyph in any prompt. Branding is opt-in
  per-invocation only.

### Measured conformance of the existing set

Modal background colour, sampled from the **`.png` masters** — the `.webp` embeds are a lossy
re-encode and shift channels by a unit or two, which is enough to reverse a channel comparison, so
they must not be used for this measurement. Deltas are against the spec ground `#FAFAF7`.

| Plate | Ground measured | ΔR | ΔG | ΔB | Gold measured (from the `.webp`) |
|---|---|---|---|---|---|
| 01 | `#F4E9D5` — this is the **band wash**, which covers most of the canvas; not the ground | −6 | −17 | −34 | `#C2A45F` |
| 02 | `#F8F7F3` | −2 | −3 | −4 | `#C7A34D` |
| 03 | `#F8F7F3` | −2 | −3 | −4 | `#CEA54F` |
| 04 | `#F8F7F3` | −2 | −3 | −4 | `#C5A051` |
| 05 | `#F8F7F3` | −2 | −3 | −4 | `#CDA857` |
| 06 | `#F9FAF5` | −1 | **+0** | −2 | `#C5A04F` |
| 07 | `#FCFBF9` | +2 | +1 | +2 | `#C4A557` |
| 08 | `#F6F5F1` | −4 | −5 | −6 | `#CAA554` |

**Finding — DS-1 (MAJOR, and narrower than it first looked).** **No plate lands on the specified
ground.** Six of the seven measurable grounds (01's row measures a wash, not a ground, and is not
evidence for this finding) hold the spec's warm ordering R > G > B and miss it by two to six units
per channel; plate 06 alone inverts R and G, **by one unit**, which is a rounding artifact and not
a visible cast. Gold drifts by up to 12 in a channel, which is the larger deviation.

**An earlier draft of this finding claimed plates 02, 04 and 06 were "green-cast". That was wrong,
and it was wrong because it was measured from the `.webp` derivatives rather than the masters** —
the re-encode moved G above R by a single unit in two of them. Recorded here rather than quietly
corrected, because it is the same class of error this audit charges the plates with: a confident
claim from a convenient source instead of the authoritative one.

What survives is the point that matters: an image model does not honour an exact hex, so brand
colour cannot be *asserted* through generation, only *approximated* and then checked. A site that
places these plates beside HTML painted with the literal tokens will show a seam. That is an
argument for measuring every generated plate on arrival — not for the provenance mechanism in Job 2,
which addresses a different failure.

**Finding — DS-2 (MAJOR).** **Plate 01 is set in a monospace face.** Every string in it — the title
and all fourteen labels — has uniform character advance. The design system requires geometric sans.
Plate 01 and plate 07 were re-rendered on the same day (`docs/diagrams/README.md`, the line
beginning "Plates `01-architecture` and `07-what-runs` were re-rendered on 2026-09-10"), and 07 is
correctly set in geometric sans — so the set is internally inconsistent as well as off-spec.

**Finding — DS-3 (MINOR).** **Headings are bold on plates 01, 03, 06 and 08**, against the explicit
rule "Headlines stay at weight 400. Bold display headings read as shouting." Plates 02, 04, 05 and
07 hold the rule. Half the set breaks it.

**Finding — DS-4 (MINOR).** **Plate 03's gold beat is two elements**, not one — the `exchange RFC
8693` arrow and the `agent-scoped token` arrow are both rendered as thick gold. `prompts.md` names
the beat as "the exchange arrow pair", which concedes the point. Defensible as one *idea*; it is
not one *element*, which is what the rule says.

# Job 2 — the diagram set the website needs

## The lane decision, and what it costs

**One lane. Every plate is a generated image delivered as `.webp`.** Mermaid and `drawio-architect`
are out by decision; the question per concept is *which image skill*, not *which lane*. The
available skills are `visualize` (orchestrator), `technical-diagram`, `isometric`, `framework`,
`concept-map`, `timeline`, `taxonomy`, `comparison`.

The `visualize` orchestrator was run over the concepts list and its routing table applied per
concept; each selection below carries the orchestrator's reasoning, not just its name.

**Where the orchestrator's routing and the one-lane decision disagree, and how it was resolved.**
The orchestrator routes "flowchart, sequence, state, class, ER" to `mermaid` — which is exactly the
shape of five of the eight requested concepts (P3, P5, P6, P7, P10). With `mermaid` removed, those
five route to their nearest available neighbour, `technical-diagram` ("freeform boxes-arrows-labels
engineering diagram"), which draws the same content without the grammar. **This is a real loss and
it is recorded, not papered over:** a state machine drawn as a freeform diagram has no parser to
reject a missing state, so the correctness burden moves entirely onto the prompt, the text
alternative, and the review. The two mitigations below exist because of it.

### Cost 1 — a generated image cannot be diffed against code

Mermaid source could have been CI-checked against the enum it draws. A `.webp` cannot. Drift
protection has to come from elsewhere. **Proposed mechanism — three parts, all mechanical:**

**(a) Every plate commits its prompt.** The `docs/diagrams/prompts.md` convention already exists;
extend it so each plate's section is complete enough to regenerate without re-deciding anything.

**(b) Every plate commits a provenance record naming the commit whose behaviour it depicts.** Add a
sibling `docs/diagrams/provenance.yaml`, one entry per plate:

```yaml
- plate: 10-auth-transaction
  depicts_commit: 22b65c2          # the commit whose behaviour this plate draws
  reverified: "2026-09-22 — stages re-read from authtxn.go:60-66; no change"
  generated: 2026-09-22
  claim_class: measured
  sources_of_truth:                # files whose change may invalidate this plate
    - internal/controller/authtxn.go
    - api/v1alpha1/agent_types.go
  proven_by:                       # required when claim_class is `measured`
    - test/e2e/lock_test.go::TestAServedNoneAgentIsLockedInPlace
  alt_text_file: docs/diagrams/alt/10-auth-transaction.md
```

**(c) A CI check turns that record into a failing test.** For each plate, `git diff --name-only
<depicts_commit>..HEAD` intersected with `sources_of_truth`; a non-empty intersection fails with
*"plate `10-auth-transaction` depicts `22b65c2`; `internal/controller/authtxn.go` has changed since.
Re-verify the plate and bump `depicts_commit` with a `reverified:` note, or re-generate it."*

**Three limits, stated because the mechanism is weaker than it looks:**

1. **It surfaces a change in a diff; it does not guarantee one is caught.** It only watches files a
   human remembered to list. It is a stale-marker check, not a correctness check — claiming more
   would be the same error the plates make.
2. **Its remedy can silence it.** A one-line `depicts_commit` bump clears the failure whether or not
   anyone looked at the plate, which is why the `reverified:` field is required alongside and must
   say what was re-read. A bump without one should fail review.
3. **`actions/checkout` must be deepened, or the check cannot run at all.** Every checkout in
   `.github/workflows/` uses the action's default shallow clone, under which
   `git diff <depicts_commit>..HEAD` fails `fatal: bad object` on every plate on every run. The job
   needs `with: fetch-depth: 0` (or an explicit `--deepen`), at the cost of a full-history clone on
   that job.

The same CI job should carry the **metadata assertion** from the EXIF section: parse each plate
**listed in `provenance.yaml`** and fail on any `tEXt`/`iTXt`/`zTXt`/`eXIf` or `EXIF`/`XMP `/`ICCP`
chunk. Pure standard library; no `exiftool` dependency. **Scoping it to the manifest is not
incidental** — all eight existing PNG masters carry an `hf-job-id` `tEXt` chunk, and the verdicts
above withdraw those plates from the *site*, not from the repository. A check written over
`docs/diagrams/*.png` would therefore land permanently red on its first commit.

This matters most for the two plates whose subjects change under them fastest — **P3 (the auth
transaction)** and **P5 (the attribution gate)**. Both sit on `internal/controller/authtxn.go`,
which design 03's amendment stream has rewritten repeatedly (A75, A77, A80, A81 in three weeks).
Both should be regenerated as a matter of course whenever that file changes, not merely flagged.

**A fourth part, recommended and cheaper than all three:** put the **claim-class marker inside the
artwork**. A plate that carries the word *designed* in its own pixels stays honest when it is
screenshotted, reposted, or read after its caption is lost. See the legend note at the end.

### Cost 2 — an image is invisible to a screen reader and to search

Each plate below carries a **text alternative**: prose that conveys the same information, which for
a state machine means naming the states and the transitions in words. These are **content**, not
`alt` attributes — too long for one, and written to stand alone. The proposal is one file per plate
under `docs/diagrams/alt/`, rendered on the page beneath or behind a disclosure control, and
referenced from `provenance.yaml` so a missing one fails CI. Writing them after the images is how
they end up useless, so each is drafted here.

### P3 · The auth transaction and its stages

**This plate must not be drawn from the brief's stage list.** The brief gave
`PreparingRoute → ApplyingPolicies → Converging → ProbingAfter → Publishing → Served`. Checked
against the code, that list is **wrong in two ways**, and the plate has to be drawn from the
constants:

`internal/controller/authtxn.go:60-66` defines seven stage constants:
`Refused`, **`ProbingBefore`**, `PreparingRoute`, `ApplyingPolicies`, `Converging`, `ProbingAfter`,
`Publishing`.

1. **`ProbingBefore` is missing from the brief's list and is load-bearing** — it is where a `Lock`
   takes its single before-answer, and `BeforeObserved` (`api/v1alpha1/agent_types.go`, the
   `BeforeObserved` field) exists only to record its result.
2. **`Served` is not a stage.** There is no `StageServed` constant; the string "Served" appears in
   Go only as a test-table label in `internal/controller/authnone_golden_test.go:90`. The highest
   stage written is `StagePublishing` (`authtxn.go:855`, `:1337`). **"Served" is the condition that
   `status.auth.mode` is recorded *and the transaction slot is empty*** — which is exactly how the
   code tests for it: `authtxn.go:392`, `if !r.Gateway.Enabled || auth == nil || auth.Mode == "" ||
   auth.Transaction != nil`. `authtxn.go:2506-2508` confirms the sequencing: a `Create` at
   `Publishing` writes the route "before `status.auth` records the mode at `Served`".

   **So `Served` must be drawn as the transaction slot emptying, not as a seventh box.** That is
   literally how it is written: `servedRecord` (`authtxn.go:1548-1561`) returns a fresh
   `AuthStatus` carrying `Mode`, `KeySource`, `AdmittedGroups`, `AppliedDigest` and `Verified` and
   **no `Transaction`**, and `recordServed` (`:1564-1579`) assigns it wholesale.

   **This is a difference of abstraction level, not a defect in the design.** Design 03 — whose
   first slice is the approved one — names `Served` as the terminal member of the chain in §1.1
   itself (`docs/designs/03-policy-compiler.md:46`, and again for `Lock` at `:47` and `:694`), and
   it is right to: `Served` is the transaction's terminal *outcome*, and the code records that
   outcome by emptying the slot rather than by writing a seventh stage value. **The plate must draw
   the design's `Served`, in the code's shape.** The one thing worth correcting is the CRD field

### P11 · The tool allowlist removes rather than refuses — *added; the brief did not ask for it*

**Why added:** it is measured, it is genuinely counter-intuitive, and it has an operational
consequence a user will hit — a refused tool call returns `Unknown tool`, not a forbidden error,
which is good for non-disclosure and a trap for whoever debugs it. A concepts section that omits it

- **Skill: `comparison`.** Exactly two states, and the contrast *is* the content.
- **Claim class: measured.** `test/e2e/mcp_test.go` — flipping the rule inverts the listing and both
  calls.

  all, and calling it anyway returns "Unknown tool" rather than "forbidden".*
- **Gold beat:** the absent row in the right-hand `tools/list` response.
- **Sources of truth:** `test/e2e/mcp_test.go`, `test/mcpserver/`.

  flat. Both panels show the same three-step exchange as small ink rows: `initialize`, `tools/list`,

## The legend the site needs

Not a plate. A small, repeated page component beside every diagram, carrying three swatches and one
line of text each — the same three classes this audit judges by, and no fourth:

| Swatch | Class | Definition on the page |
|---|---|---|
| solid gold | **measured** | A named test in this repository proves it. |
| solid grey | **designed** | A design or the architecture specifies it. Nothing enforces it. |
| dashed grey `#999999` | **not built** | No implementing code. |

Every plate above is specified so that its artwork uses those three treatments, which is what makes
the legend work and what stops X-2 from recurring. **Two rules keep it honest:**

1. **Whatever a plate draws in solid gold, its `provenance.yaml` entry must name the test that
   proves it, in `proven_by`.** A `measured` class with an empty `proven_by` should fail the CI
   check alongside the staleness test. A draft of this proposal classed four plates `measured` and
   cited a test on none of them; the rule exists because that is the easy mistake.
2. **No plate may invent a fourth class.** A draft of P12 used "measured history", which the legend
   cannot render. If a distinction is worth drawing and does not fit these three, it belongs in the
   plate's own key — as P12's filled/open tick marks now do — not in the shared legend.
