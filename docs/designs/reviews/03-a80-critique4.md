### MAJOR 1 — the errored pass gets its condition back and nothing gives it back its `Ready`, so the transient arm still reads `Ready=True` on a refused route; and the only edit that closes it moves A75's caller arm, which A80's scope claim says nothing moves

### MAJOR 2 — the stated mechanism omits `gatewayOutcome.served`, so it produces phase `Pending` and actively CLEARS `Degraded`, against two §5 rows and six case-19 rows — the defect this file's own comment records being reintroduced once already

`03:835`, against `03:824`, `03:825`, `03:1349`, `03:1350`, `03:1421`–`03:1432`, and `internal/controller/agent_controller.go:943`–`:958`, `:832`–`:840`, `internal/controller/authtxn.go:121`–`:128`, `:1498`–`:1541`.

```go

if gw.served {                                   // :953
    conds.set(CondDegraded, ConditionTrue, w.reason, w.message)
    status.Phase = PhaseDegraded
    return
}
status.Phase = PhasePending                      // :958
```

`gatewayOutcome`'s own comment says so: "served says whether the Agent was serving, **which decides Degraded over Pending**" (`authtxn.go:125`–`:126`). `03:835` is the paragraph written *because* "the plausible placements do not agree", and it enumerates the mechanism down to function names — `raiseIncomplete`, `withholdInOrder`, `gatewayOutcome.withhold`, `withholdReady` — and omits `served`. An implementer following it literally gets `Ready=False`, **phase `Pending`, and no `Degraded` condition at all**, which contradicts `03:824`, `03:825`, §5's two new rows at `03:1349` and `03:1350`, and case 19 (a), (b), (e), (f), (h) and (l), every one of which asserts phase `Degraded`.

### MAJOR 3 — the replacement for the relegated-reason rule is not computable either: it names a vehicle that cannot write `GovernanceSkipped`, rests on a premise the code contradicts, specifies no way to recognise a message-only claim, and resolves fail-open on the one condition that announces the unauthenticated window

`03:827`, against `03:825`, `03:841`, `03:1350`, `03:1426`, `03:1431`, and `internal/controller/authtxn.go:500`–`:512`, `:414`–`:454`, `internal/controller/conditions.go:56`–`:58`, `:119`–`:130`, `internal/controller/httproute.go:695`–`:762`.

The diagnosis is right — a reason match cannot restore a report another cause has relegated to a message — and the first clause of the new rule is right. The rest has four defects, and they compound.

- **The named vehicle cannot write the condition it is named for.** "a report the stored condition carries only inside its message is re-appended, **through `raiseIncomplete`**". `raiseIncomplete` hardcodes `CondPolicyApplyIncomplete` at all four of its writes (`authtxn.go:501`, `:504`, `:507`, `:510`). `GovernanceSkipped` is exactly where `AuthPolicyNotAttached` is a message fragment **by design** (`03:841`), so the vehicle is unavailable in the case the sentence exists for.
- **The premise is false.** "On `GovernanceSkipped` there is often no stored condition to restore at all — `assessGovernance` rewrites it twice a pass and `reportForeign` writes it from scratch". `GovernanceSkipped` is owned **and sticky** (`conditions.go:119`–`:130`), so once set it is always present in stored status. What `assessGovernance` rewrites is the *pass's* assertion, not the stored condition. And `seedStoredAbove` does precisely what the sentence says never happens: it restores the stored `GovernanceSkipped` **as a whole condition**, over `assessGovernance`'s fresh value, for `ForeignTrafficPolicy` (`authtxn.go:428`–`:438`) and for W1's `GatewayAuthPolicy` (`:441`–`:452`). The precedent for restoring it whole is shipped code.
- **So "never restored as a whole condition" resolves fail-open.** In the ordinary policy half — no foreign policy, no Gateway-level policy — the stored `GovernanceSkipped`'s reason **is** `AuthPolicyNotAttached`, and `assessGovernance` has already derived `False`/`AuthVerifiedOnOneReplica` for a served `apikey` Agent (`httproute.go:750`–`:753`). Appending a fragment to that leaves the Agent reading **`GovernanceSkipped=False`, "auth verified on one replica", while its `-auth` is attached to nothing** — the exact claim `03:825` and `03:1350` require to read `True`, retracted on every unknown pass and restored on the next. `PolicyApplyIncomplete` and `Ready=False` still stand, so the Agent contradicts itself rather than lying quietly, but rule 8 applies to each condition on its own and this is the loud-and-wrong kind on the fail-open half. Case 19 (k)'s second half ("the same for the policy half") would fail against the rule as written, and case 19 (f) asserts the opposite value.
- **Nothing says how a message-only claim is recognised.** The only place such a claim exists is inside a concatenated human-readable string, and `raiseIncomplete` and `reportAboveServed` both compose with the same `" | "` separator (`authtxn.go:507`, `:510`, `:367`–`:369`), so its extent is ambiguous. Nothing in the shipped operator reads a condition message for state; the nearest precedent, `strings.TrimSuffix(stored.Message, carriedNote)` (`:321`), is a suffix trim. A design this careful about determinism should not leave a message parse as the store for the property the amendment exists to establish.

**Fix.** Three clauses in `03:827`. (i) Strike "and never restored as a whole condition" and the premise sentence, and say instead that on `GovernanceSkipped` a stored `AuthPolicyNotAttached` is re-asserted whole, on `seedStoredAbove`'s precedent, and only a fragment under another reason is re-appended. (ii) Replace "through `raiseIncomplete`" with a per-condition statement: `raiseIncomplete` on `PolicyApplyIncomplete`, and a stated composition of its own on `GovernanceSkipped` that says what happens to `LastTransitionTime` and to the hold marker there. (iii) Name how a fragment is recognised — an explicit marker the operator writes and matches, or two fields on `status.auth` with the `crds/`/`helm upgrade` hazard the (A2) cell already states — and cost whichever is chosen. Then extend case 19 (k)'s third half to assert `GovernanceSkipped` as well as `PolicyApplyIncomplete`.
