## Findings

1. **MAJOR — `test/envtest/pin_test.go:979–995`, `test/envtest/a29_test.go:109–138`: too early and too late both pass all focused tests.** The CRD-disappearance test records `GatesPassed` before the detector is turned off, then checks it only *after* two passes with the detector back on. Nothing that `assessPromotedGate` reads changes. Reasserting the same reading on the excluded pass therefore passes. Conversely, the new rows change the spec before their discriminating assertions. An optimization that skips re-deriving a current-generation condition for an already-active pin passes too, although status-only changes to the eval record must affect the next enforced promotion-branch pass. Both mutants compiled and survived the focused battery (below). This distinguishes a comparison of values from testing *which pass* produced them.

   **Fix:** extend the existing CRD-return row. With B pinned and initially `False/ActiveRevisionNotEvaluated`, turn the detector off and, without modifying the spec, write a `Passed` pair for B using `writeAgentStatus` (a controlled input, not a claim that the eval controller initiates a run while the CRD is absent). Drive one pass: the old false condition must remain. Turn detection on; drive exactly one pass: now require `True/EvalPassed` for B and the recorded suite. A temporary reviewer row with these inputs passed on pristine HEAD and killed both mutants at **different assertions** at generation 4. No production change needed.

2. **MINOR — `test/envtest/a29_test.go:21–30`, `internal/controller/agent_controller.go:2253–2255`: the warning that qualifies the pinned message is not pinned.** Removing only “except on a pass that stops earlier, such as one on an unresolved env source” left the focused battery green; the condition now says without qualification that `GatesBypassed` or `Degraded` describes the pin. The approved design expressly retains paths on which it need not. The implementation's text is correct. **Fix:** assert the exact approved suffix with `strings.HasSuffix` in `a29UnevaluatedPin`, or in a focused pinned unit case.

3. **MINOR — `internal/controller/passunrecorded_test.go:203–204`: one explicitly listed companion comment was missed.** It still describes the reader only “when the spec mints the active revision.” Design 16 A29.1's implementation list (`docs/designs/16-evalsuite.md:1749`) also calls for it to say this for a pinned revision. The signature changes three lines below do not change the comment. **Fix:** mention that the promotion branch reads the entry for the serving revision, including a revision selected by pin, with the pin behavior exercised in envtest.

4. **MINOR (process/provenance) — `docs/designs/16-evalsuite.md:1703,1770–1773`: the exact A29.4 process did not occur.** The decision itself is unambiguous. The record says A29.4 was taken as recommended, but that item calls for a docs-only decision/registry/index change followed by the implementation fold. Against `fe9a52a` there is a single mixed commit and no independently identifiable docs-only decision change. Saying that no *separate PR* was merged does not identify a docs-only change. **Fix:** preserve a docs-only decision/registry/index commit before the implementation commit in the draft, or explicitly label the combined packaging as a process deviation rather than attributing it to the user's choice. This is not a request to change option (b), merge #164, or open two PRs.
