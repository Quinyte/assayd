## BLOCKER 1 — In every case row 4 exists for, the handler's workload list is non-empty, so the recreated tenant is re-adopted or flaps

**Files:** `docs/designs/02-agent-crd-operator.md:172,186,137,194`

Row 4 (02:172) fires when `sourceNamespaceUID` ≠ the current `S`'s UID — the tenant was deleted and recreated — and says "the handler's list is scoped by the binding's source UID, so the Agent that triggered this row does not count against the deletion." True of the *Agent* list. Handler step 3 (02:186) then also lists "the workloads and copies in the run namespace that belong to any Agent other than the one reconciling. If **either** is non-empty → compare-and-swap back to `Bound` and proceed as row 12."

Row 4 is reachable only when the old tenant's Agent finalizers did not run: a normal deletion of `S` runs every finalizer, the last one deletes the run namespace, the Namespace-keyed reconciler's step 1 deletes the binding, and the recreated tenant hits row 2. And "nothing collects a workload but the finalizer" (02:137). So whenever row 4 fires, the old tenant's Deployments and copies are still in `R`, labelled with a `plume.dev/agent-uid` that names no Agent that exists. They are "workloads that belong to an Agent other than the one reconciling". Step 3's second list is non-empty **by construction** in the row's only scenario.

**Failure scenario:** `team-a` (u1) has Agent `X` with Deployment and copies in `R`. A human removes `X`'s finalizer and deletes `team-a`; `R` keeps `X`'s workloads, `X`'s copies, u1's read-only RoleBinding. `team-a` is recreated as u2 by another team; its first Agent `Y` reconciles. Row 4: CAS → `Terminating`, handler. Step 1: `R` present. Step 2: no deletion timestamp. Step 3: Agents in `S` scoped by u1 → empty; workloads in `R` other than `Y`'s → `X`'s → **non-empty** → CAS back to `Bound`, "proceed as row 12": `Y`'s Secret copies and Deployment are written into u1's namespace, beside u1's still-running Pods, under u1's RoleBinding. That is the refusal 02:136 states ("its RoleBindings were built for a different tenant's subjects") and the exact re-adoption r2 BLOCKER 1 described, reached through the predicate added to close r2 MAJOR 3. The other reading — "proceed as row 12" re-enters the table from the top — hits row 4 again and flaps `Terminating`↔`Bound` on every reconcile, and §5's row (02:431) promises the condition "clears when the handler has removed the namespace", which it never does.

The same predicate also holds a **live** tenant's namespace open forever: if one Agent `Z` in `S` has its finalizer bypassed, `Z`'s orphaned Deployment makes every later finalizer's step 1 (02:194) find "another Agent's workload remains", so no Agent is ever last, and `R` outlives `S`'s last real Agent with `Z`'s Pods still holding SVIDs. The design's "nothing is force-killed silently" is about a *drain*, and an orphan is not draining — no finalizer is running for it.

**Fix:** scope the workload list the way the Agent list is scoped. Step 3 and finalizer step 1 count a workload or copy only if its `plume.dev/agent-uid` names an Agent that currently exists in `S` (deleting or not) **and** `S`'s UID equals the binding's `sourceNamespaceUID`. Everything else in `R` is an orphan and goes with the namespace — say so, and say the delete is logged and evented on the Namespace because no Agent exists to carry a condition. Then row 4's sentence becomes true ("both lists are empty for a recreated tenant") and row 4 should CAS only from `Creating` or `Bound`, leaving `Terminating`/`Deleting` to row 5, so a UID mismatch cannot re-open a `Deleting` binding. Add the envtest r2 asked for by name at 02:204 — it is listed as "one per numbered row", which is what let this through; name it: *source namespace recreated under a `Bound` binding whose run namespace still holds the old tenant's Deployment → old namespace deleted, nothing written into it, new one created* — and a second: *one Agent's finalizer bypassed, the last real Agent deleted → run namespace deleted*.

## MAJOR 1 — The pristine check assumes a freshly created namespace contains no RoleBinding or ServiceAccount, and on any cluster where that is false every tenant goes terminal

**Files:** `docs/designs/02-agent-crd-operator.md:161,175,176,138` · `docs/designs/07-umbrella-chart-ci.md:192-198`

02:161: binding requires the namespace to contain "no `Role`, `RoleBinding`, `Pod` or non-default `ServiceAccount`"; row 8 (02:176) makes a failure **terminal** `NotCreatedByOperator`. Row 7 is not a crash-only path: every namespace the operator creates passes through it on the next reconcile after row 6. So the check runs on every tenant, on every install.

The premise — a namespace the operator just created is empty of RBAC — is a property of the cluster, not of the operator, and it is false on common clusters: OpenShift's default-rolebinding controller writes `system:image-pullers`, `system:image-builders` and `system:deployers` RoleBindings and the `builder`/`deployer` ServiceAccounts into every namespace at creation; Kyverno and Gatekeeper `generate` policies that stamp a RoleBinding or a default ServiceAccount into every new namespace are a documented, common pattern; Rancher project membership does the same. Design 07's own premise is NFR-3, "runs anywhere" (07:9), and design 26 soft mode is "Capsule-style tenant policy" (26:38) — Capsule generates owner RoleBindings in the namespaces it considers a tenant's, and whether an operator-created `plume-run-*` is one depends on installer configuration the design does not state.

**Failure scenario:** `helm install plume` on a cluster with a Kyverno policy that generates a `namespace-viewers` RoleBinding in every namespace. First Agent: row 2, row 6, row 7 — RoleBinding present → row 8 → `RunNamespaceUnavailable=NotCreatedByOperator`, terminal, for **every** tenant, with a message that says "check whether it was pre-created, or deleted and recreated outside the operator" (02:429) — neither of which happened. There is no allowlist, no way to learn which object tripped it, and the re-bind procedure (02:200) recreates the binding in `Bound` from a UID, which then passes row 12 — so the human's only recovery is to bypass the check by hand for each tenant, which is worse than the check not existing.

A second, internal instance of the same trap: the read-only RoleBinding the operator "maintains" in the run namespace (02:138) is a RoleBinding. If the implementation writes it at row 6 or before row 7's check, the operator fails its own pristine check on every namespace. Nothing says it is written only after `Bound`.

**Fix:** (1) state the premise as a premise: "the check assumes no admission or policy controller writes RBAC into a new namespace"; (2) the condition message names the offending object's kind and name (NFR-8) — an admin who reads `NotCreatedByOperator: rolebinding/namespace-viewers` knows what to do, one who reads "check whether it was pre-created" does not; (3) a chart value (`runNamespace.pristineAllow: [{kind, name}]`) that names objects an admin vouches for, with the note that an allowlisted RoleBinding is trusted by the installer, not by the operator; (4) say the operator writes its own RoleBinding only after `Bound`, and that row 7's check excludes nothing else. Add the grants the check needs to 07 A5.7 (MINOR 7) — they are cluster-wide reads of every RoleBinding and ServiceAccount, which is a real widening A5.7's title promises to name.

## MAJOR 2 — "It reaches no spec and no workload" is false: `agents/status` is the operator's state, and A37's collision guard rests on the operator alone writing it

**Files:** `docs/designs/26-tenant-cr.md:85,116` · `docs/designs/02-agent-crd-operator.md:224,220,420`

26:85 (§7's new parenthetical): "A1 adds exactly one tenant-side write, `agents/status` `patch`, for the `RoutesRevoked` signal; it reaches no spec and no workload." r2 MAJOR 6 asked the design to *say* what status-write reaches; the amendment instead asserts it reaches nothing.

02:420: "no state outside CR status + directory KV" — status **is** the operator's state. 02:224 (A37): "the check is: `status.activeRevisionDigest` (and the candidate's) is **written only by the operator through the status subresource, under separate RBAC**" — that sentence is the premise of the whole collision guard, and A1 hands that RBAC to the compiler inside every hard-mode vCluster. 02:220 describes what a principal who controls that field gets: the operator "sees `activeRevision == desired`, skips candidate gating entirely, and converges the Deployment … to the malicious image."

**Failure scenario:** a compromised host compiler and a hard-mode tenant editor — the two principals the design already treats as adversarial to the gate — cooperate. The editor writes an ungated spec; the compiler patches `status.activeRevisionDigest` to that spec's digest; the tenant's agent-operator, on its next reconcile, finds active == desired, mints no candidate, runs no gate, and creates and serves the Deployment. In hard mode the compiler also writes the routes, so it needs nobody's help to send traffic there. §7's sentence "a compromised compiler cannot create workloads in any tenant" fails — not through `spec`, as r2 MAJOR 6 showed for `agents patch`, but through the field A37 says only the operator may write. The parenthetical that was added to make §7 honest makes it wrong.

**Fix:** either move the signal off Agent status, or fence the write. Off status: the compiler writes `RoutesRevoked` as a ConfigMap or Lease in a vCluster namespace that holds nothing else (**not** the tenant operator's namespace, which holds the binding records), with `create`/`patch` on that one kind in that one namespace; the tenant operator reads it. Fenced: keep `agents/status patch` and ship a `ValidatingAdmissionPolicy` in the vCluster that permits the compiler's ServiceAccount to change only `status.conditions[type=RoutesRevoked]` — `oldObject`/`object` comparison in CEL expresses "nothing else changed", and it is a library, not a server. Either way, 26:85 must say what the write can reach, and 02 A37 (02:224) must name the second writer or the fence, because its "written only by the operator" is what the guard rests on.

## MAJOR 3 — Handler step 1 deletes the binding without reading its state, and races row 9 into a terminal condition on a healthy tenant

**Files:** `docs/designs/02-agent-crd-operator.md:182,184,177,169`

02:182: the handler "has one owner: whoever reads the state" and runs from the Namespace-keyed reconciler on every event for a labelled `plume-run-*` namespace. Steps 3-5 are conditioned on `Terminating` / `Deleting`. Steps 1 and 2 are not: "1. Run namespace absent → delete the binding." Row 9 (02:177) handles the same observation — `Bound`, namespace absent — differently: "the binding returns to `Creating` with a new nonce and the namespace is recreated." Two rules for one case, which A32 in this design already names as the defect where an implementer picks one.

**Failure scenario:** a cluster admin deletes `R`. The Namespace informer emits the delete; the Deployment watch maps the dying Deployment to Agent `X`. Two controllers, two workqueues. `X`'s reconcile: row 9 → CAS `Bound`→`Creating`, new nonce → row 6 → create `R'`. The Namespace reconciler's run lands between those two writes: handler step 1, `R` absent → delete the binding. `X`'s row 6 creates `R'`. `X`'s next reconcile: no binding, `R'` exists → **row 1: `NotCreatedByOperator`, terminal** (02:169), for every Agent in `S`, with a message telling the human to check for pre-creation. The same interleaving is reachable from step 2's requeue firing after `R` goes absent. The window is one API round-trip inside `X`'s reconcile; it needs no attacker and no crash, only the two reconcilers the design registers.

The Namespace-keyed reconciler's behaviour when the binding is **absent** is also unstated — an attacker's pre-created namespace wearing the label wakes it, and the handler has no state to read.

**Fix:** gate the handler's entry on state, as its name promises: the Namespace-keyed reconciler and row-5 entry act only when the binding exists and is `Terminating` or `Deleting`; otherwise they do nothing and log. Row 9 alone owns `Bound` + absent; row 6 alone owns `Creating` + absent. Step 1 then reads "state `Terminating` or `Deleting`, run namespace absent → delete the binding." Add the interleaving to 02:204's crash-point list: *Namespace reconciler between row 9's swap and row 6's create*.

## MINOR

1. **The `state` field lists three states; the protocol has four** (02:157 vs 02:187). An implementer who builds the enum from the field table has no `Deleting`. Add it.
2. **Row 2's loser "continue[s] from 4", skipping row 3** (02:170). `AlreadyExists` on the binding create "means another reconcile of `S` won" — or a reconcile of the colliding tenant `S'`, which is the *chosen collision* case r8 owes a test for (02:204). The loser then hits row 4 (source UID ≠ its own), CASes the winner's fresh binding to `Terminating`, and the handler's step 1 finds the namespace not yet created and deletes the winner's binding; the winner's next pass is row 1, terminal. The reachability is a 64-bit second preimage on design 03's hash (03:159), so this is a wording defect the owed test would expose, not a live attack. "Continue from 3".
3. **Step 5's UID mismatch wedges the tenant with only a log line** (02:188, 02:431). "Anything else is refused and logged" leaves the binding in `Deleting` forever with an attacker's namespace at the name; every Agent in `S` waits at `Terminating` and §5 says that "needs no human unless the delete itself is refused" — how would the human know? The right outcome for a UID mismatch at step 5 is the one row 11 already gives the same observation: delete the binding, let the next reconcile hit row 1's terminal condition, which names itself.
4. **Row 10 "starts fresh via row 9's path"** (02:178) — the handler's step 1 deletes the binding when the namespace is gone, so the path is row 2's, and row 9's note that the deletion is recorded as a material loss (A41) applies to row 10 too. Say "row 2, with row 9's consequence".
5. **The `creationTimestamp` clause is decorative** (02:161). "Not earlier than the binding's" rejects a namespace older than the binding — pre-creation — which the nonce already rejects. r2 proposed an *upper* bound; the amendment took the lower one, which no attack fails. Drop it, or keep it and say it is belt.
6. **Pristine does not include `metadata.finalizers`** (02:161, 02:431). A recreator with only namespace `create` sets finalizers on the object it creates; a bound namespace carrying a foreign finalizer never becomes absent, step 2 requeues forever, and §5's "needs no human unless the delete itself is refused" is wrong for a delete that was accepted. The principal can already wedge a tenant via row 11, so this changes nothing in tier; the §5 sentence and the pristine definition should both name it.
7. **The pristine check's grants are missing from A5.7** (07:192-198, 02:161). Listing `roles`, `rolebindings`, `serviceaccounts` and `pods` in a namespace RBAC cannot name means cluster-wide `list` on every RoleBinding and ServiceAccount in the cluster. A5.7's title is "the escalations, named" and its last line says "the ClusterRole today grants none of these"; add the row so the claim of completeness stays true.
8. **Step 3's failed swap back to `Bound` is unspecified** (02:186). Step 4 says what a failed swap means; step 3 does not. When another worker already restored `Bound`, the finalizer's step 3 (02:196) does the right thing — "has restored `Bound`" — but only if the handler reports it. One clause.
9. **`AwaitingRouteRevocation` has no condition type** (26:116, 02:455, 02:804). 26 A1 has the tenant operator set "design 02 §5's finalization-stalled condition naming the step" — 02:455 says "condition names the stuck step" and names no type, and A52 closed the vocabulary in Go, so a type not in the 39 cannot be set. Name it in 02 §5 (a `FinalizationStalled` type, count 40, or a reason on `Progressing`) and update the count at 02:782.
10. **Two r2 findings became debts with no marker where a reader would look** (26:122). Design 27 must consume `GatesTenantAdminBypassable`; design 24 must put the trust domain in the subject mapping. `27-compliance-packs.md` and `24-authz-provider.md` are untouched and `README.md` rows 24 and 27 say "critique PASS" with nothing owed. The corpus's own rule (26:112: "propagation is the failure this cross-design pass keeps finding") argues for a one-line "owed by 26 A1" marker in each README row, so the debt survives this review file.

## Where the work is right

Tried to break these and could not:

- **The ordered rows** (02:165-180) are the right structure and the precedence sentence names the exact case that would pool. Rows 3 and 11 cannot be reached by a second tenant without a 64-bit second preimage or cluster rights, and both are terminal without writing.
- **The `Deleting` fence** (02:187-190) closes r2 MAJOR 2 as stated: a creator that read `Terminating` is either in the next list or waiting on `Deleting`; a creator that read `Bound` is in the list. Two finalizers past their delete step both find empty lists, one wins each CAS, the other re-reads and reissues an idempotent delete. Traced every interleaving I could construct with a live Agent; none deletes under it.
- **The drain predicate** (02:194) is right for the case it was written for — two `kubectl delete -f dir/` Agents within one `taskTimeout` — and BLOCKER 1 is what it also counts, not what it fails to count.
- **The pristine bind** (02:161) is the right *shape*: bounding the gap by a check rather than a duration is the correct answer to r2 MAJOR 4, and "a recreate that adds its RoleBinding after the bind needs `rolebindings create`, which namespace `create` does not confer" is true — I could not find a way for a namespace-create+delete principal to gain write into a bound namespace. MAJOR 1 is the premise the check makes about *other* controllers, not about the attacker.
- **The two-proof paragraph** (02:159) and the retitled row (02:136) now say one thing, and §5 (02:429) says the same thing.
- **Row 2's nonce-from-the-binding rule** (02:170) is exactly r2 MINOR 12's fix.
- **The re-bind** (02:200) asks the human for the two values `Bound` reads and no others, and names the trigger `cmd/operator/main.go:58-61` documents.
- **26 A1 point 4's order** — compiler drains and revokes, tenant operator waits — is right, and placing R3-a's finalizer with the tenant operator is the correct reading of "blocks removal until host cleanup confirms". MAJOR 2 is about what the signalling grant can also do, not about the order.
- **26 A1 point 2** now says what the host boundary protects and what it does not.
- **`RoutesRevoked` foreign to the owned set**: `conditions.go:44` is the owned map and `:89` is the branch that clears only owned types. Verified.
- **The Namespace-keyed reconciler's predicate** — `pods-by` plus name shape, not `run-namespace` — is right and its reason (26 A1 point 1) is stated where the reader needs it.

## Verdict

**design 02 A60 §3.2 / design 26 A1: REVISE** — 1 BLOCKER, 3 MAJOR, 10 MINOR. The substance has converged: nothing here changes the instruments, and no finding asks for a new state or a new object. The BLOCKER is one scoping clause applied to the second list as it was to the first; MAJOR 3 is one state gate on one step; MAJOR 1 is a premise to state and a message to write; MAJOR 2 is the one that needs a decision — where the `RoutesRevoked` signal lives — and 02 A37's premise must be amended whichever way it goes.
