## MAJOR findings

### MAJOR 1 — the hold covers the unknown reading and not the errored pass, and on the transient arm that is the original defect, verbatim

`03:827` and `03:829` against `internal/controller/authtxn.go:297`–`:299`, `:304`–`:323`, `internal/controller/httproute.go:510`–`:513` and `internal/controller/agent_controller.go:816`–`:893`.

`03:829` scopes the judgement to "a pass where that step returned no error". `03:827` and `03:833` put both new reasons into `carriedReason`. Those two sentences together open a hole, because `carriedReason` is the **withdraw** predicate as well as the carry list:

```go
if c, ok := conds.get(CondPolicyApplyIncomplete); ok && carriedReason(c.Reason) {
    conds.unset(CondPolicyApplyIncomplete)     // authtxn.go:297–:299, before gatewayStep
}
```

Everything that can put the condition back on an error is reason-specific and none of it names A80's reasons. `pre`/`had` recaptures only `AuthPolicyMissing` and `AuthLockUnverified` (`:288`–`:291`). `storedHold` recaptures only `GatewayAuthPolicy`, and only beside a `Create` or `Lock` at `ProbingAfter` (`:393`–`:403`) — a served Agent with an empty slot fails that gate twice over. `out.aboveHold` is empty because the judgement never ran.

So for a served Agent, empty slot, standing `ServingRouteNotAccepted`, on a pass where `gatewayStep` returns an error:

- **transient** (`IsConflict`, `IsAlreadyExists`, `errRouteRaceLost`, `errStaleAgent`) — the caller takes **none** of its three arms: there is no transaction, so the second is skipped, and `gw.withhold` is nil, so the third is. `conds.merge` then drops `PolicyApplyIncomplete` and `Degraded`, which are owned and not sticky, and `Ready`/phase keep the rollout switch's `True`/`Ready` set two hundred lines above. Status **is** written on this path (`agent_controller.go:886`–`:890`). **A served Agent on a route the Gateway is still refusing reads `Ready=True`, phase `Ready`, and the clock restarts.** That is `03:827`'s own sentence — "the Agent would flip back to `Ready=True` … the original defect, re-entered through the fix" — reproduced one path over from the one the hold closes;
- **non-transient** — `agent_controller.go:831` overwrites `PolicyApplyIncomplete` with the write error's reason through `conds.set`. `Ready=False` and `Degraded` survive, so this half is not fail-open, but `ServingRouteNotAccepted` vanishes from the condition entirely rather than composing, which `raiseIncomplete` exists to prevent.

A75 built two mechanisms for exactly this pass and A80 inherits neither: `storedHold`'s lost-race restoration, and `reportAboveServed` running on `err == nil || transientRouteWrite(err)` under the comment "W1 must not clear for a pass (A75)". `03:829` opts A80 out of the second by construction.

**I disagree with the forked pass's BLOCKER grade and say so rather than defer.** The trigger is a lost race on a pass that also writes the route or the policy, and in the steady state of the measured incident — a renamed listener — nothing writes and nothing errors, so the report is raised and held for the whole incident. The window is one reconcile and self-heals. What makes it MAJOR rather than MINOR is not the frequency: it is that the amendment's single new property is "the operator does not report healthy while the Gateway refuses the route", and there is a reachable pass on which it does.

**Fix.** One sentence in `03:827`, and a clause in `03:829`: the "no error" scope governs *raising* only — a pass whose `-auth` step errored re-derived nothing, so a standing `ServingRouteNotAccepted` or `AuthPolicyNotAttached` is re-asserted from stored status the way `storedHold` re-raises A75's at `authtxn.go:319`–`:322`, extended to both reasons and to a served Agent with an empty slot; and on the non-transient arm the write error's reason composes through `raiseIncomplete` rather than replacing it. Add case 19 (l): raise (a)'s state, force a `Conflict` on the next pass's route or policy write, and assert the condition, its `LastTransitionTime` and `Ready=False` across it. Mutation: leave the error path as it stands, which is `origin/main` — one deletion, it compiles, and the row must fail.

### MAJOR 2 — "a standing report re-asserted from stored status" is not computable once the reason has been relegated to another reason's message, which A80's own ordering makes the ordinary case

`03:827` against `03:835`, `internal/controller/authtxn.go:487`–`:511` (`incompleteOrder`, `incompleteRank`, `raiseIncomplete`) and `:366`–`:372`.

A80 appends both new reasons to the **end** of `incompleteOrder`, and makes `AuthPolicyNotAttached` a message fragment on `GovernanceSkipped` by design whenever `ForeignTrafficPolicy` or `GatewayAuthPolicy` stands. §3.3.3 names those as the only states in which the appended ranks are exercised at all — so in exactly the states the ordering rule is written for, the stored condition's **reason** is somebody else's and A80's report exists only inside the message.

The hold rule says "a standing `ServingRouteNotAccepted` or `AuthPolicyNotAttached` is re-asserted from stored status". A reason match — which is what `storedHold`, `seedStoredAbove` and `carriedReason` all do, and the only thing the precedent supports — finds nothing there. Two outcomes follow, and the design chooses neither:

- **the everyday one.** W1 standing with `ServingRouteNotAccepted` in the message; a promotion makes the route reading unknown; W1 is re-derived fresh and the fragment is gone. The condition stays up and `Ready` stays withheld under `GatewayAuthPolicy`, so this is not fail-open — but the message stops naming the Gateway's refusal and names it again on the next known reading. That is the message flapping, which is what the hold rule exists to stop, and rule 8's "name the real cause" applies to the message as much as the reason;
- **the fail-open one.** The outranking cause clears on the *same* pass the reading goes unknown: the foreign policy is removed and a promotion lands in one pass. `reportForeign` does not run, the hold finds no reason match, `PolicyApplyIncomplete` is dropped, and `Ready` returns to `True` on a route the Gateway is still refusing. It needs the coincidence, which is why this is MAJOR and not a second blocker-shaped finding, but nothing in the design prevents it.

The same applies to `GovernanceSkipped`, where it is worse-defined rather than worse: `assessGovernance` rewrites that condition twice a pass (`agent_controller.go:384`, `authtxn.go:301`) and `reportForeign` rewrites it from scratch, so on an unknown pass there is no stored condition to re-assert and no stated rule for the fragment.

**Fix.** One sentence in `03:827`: what is held is the **reason's claim**, not the condition object — on an unknown reading a report that is the condition's reason is re-asserted from stored status with its `LastTransitionTime` and `ObservedGeneration`, and a report the stored condition carries only in its message is re-appended, through `raiseIncomplete`, to whatever reason this pass derives; if no other reason stands, it becomes the reason and keeps the stored `LastTransitionTime`. Add a half to case 19 (f) or (k): raise the composed state, remove the outranking cause and move the generation in one step, and assert `PolicyApplyIncomplete` still reads `ServingRouteNotAccepted` with its `LastTransitionTime` unchanged. Mutation: hold by reason match alone — one conditional, it compiles, and the half must fail.
