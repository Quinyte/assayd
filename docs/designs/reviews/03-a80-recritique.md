## MAJOR findings

### MAJOR 1 — the unknown state is said to preserve the report and A80's own carry-set instruction retracts it, so a promotion resets the page clock

`03:827` against `03:833` and `03:1473`; `internal/controller/authtxn.go:297`–`:299`; `internal/controller/conditions.go` (`ownedTypes`, `stickyTypes`).

§3.3.3's unknown paragraph: "No entry for the assayd Gateway, no condition of that type, an empty ancestor list, or a condition whose `observedGeneration` is behind the object's, **all leave the Agent exactly as the last pass left it**."

That is not what the machinery does, and A80's own remedy is what guarantees it is not. `CondPolicyApplyIncomplete` is in `ownedTypes` and **not** in `stickyTypes`, so a pass that does not assert it drops it. And `carriedReason` is not only a carry list — `reconcileGateway` uses it to **withdraw** on the way in:

```go
if c, ok := conds.get(assaydv1alpha1.CondPolicyApplyIncomplete); ok && carriedReason(c.Reason) {
    conds.unset(assaydv1alpha1.CondPolicyApplyIncomplete)   // authtxn.go:297–:299
}
```

So the moment `ServingRouteNotAccepted` and `AuthPolicyNotAttached` join `carriedReason` — which `03:833` and `03:1473` require, correctly, for MAJOR 4's reason — every pass that reaches the `-auth` step unsets them and re-derives. An unknown reading therefore produces **the same outcome as a healed one**: the condition clears, `Ready` returns to `True`, phase returns to `Ready`, and `LastTransitionTime` is reset on the next raise.

The state that makes this bite is ordinary. `metadata.generation` on the route moves when its spec moves — a promotion rewrites `backendRefs` (`httproute.go:303`–`:305`, `r.Update` at `:309`). So a served Agent whose route is standing at `Accepted=False` reads:

- pass *n*: refused at generation *g* → `ServingRouteNotAccepted`, `Ready=False`, clock starts;
- pass *n+1*, which promotes a revision: route now at *g+1*, Gateway's report still at *g* → **unknown** → condition withdrawn and not re-raised → `Ready=True`, phase `Ready`, and the Agent claims health on a route the Gateway is still refusing;
- pass *n+2*, once the Gateway reports at *g+1* → raised again, with a **new** `LastTransitionTime`.

Design 10's rule is "open >5m". A rollout inside the window restarts it. Worse, on the sub-case A80 already names — a Gateway that is readable and has stopped writing status — the report never returns at all after a route write, so the remedy **retracts** a report it had correctly raised and the Agent goes back to reporting healthy. That is the original defect, re-entered through the fix.

Note this is not the same hole as MAJOR 4's: that one was passes returning *before* the `-auth` step, and the carry set closes it. This one is passes that reach the step and read an unknown, which the carry set cannot reach because the step withdraws the seed first.

**Fix.** Decide it in one sentence, in §3.3.3's unknown paragraph, and say which:

- *hold* — "an unknown reading leaves a report the last pass raised standing, carried from stored status with its `LastTransitionTime` the way `storedHold` carries A75's, because a route write is not evidence the Gateway has accepted it; only an explicit tuple that is **not** broken at the current generation clears it"; or
- *retract* — "an unknown reading clears a standing report, so any write to the route retracts it until the Gateway reports again, and design 10's clock restarts" — which must then be named in "What the fix does NOT cover" and costed in choice A, because it is most of what (A1) is worth.

Then add case 19 (k): raise (a)'s state, promote a revision so the route's generation moves, write **no** new route status, and assert the chosen outcome — the report standing with `LastTransitionTime` unchanged, or cleared — across two reconciles. Mutation: take the other branch. It compiles, and the row must fail. **I recommend *hold***: it is what §3.3.3 already says, it is the only reading under which the page A80 rests on survives a rollout, and `storedHold`/`seedStoredAbove` are the precedent for doing it from stored status.

### MAJOR 2 — `AuthPolicyNotAttached` is a `GovernanceSkipped` reason, and A80 orders only `PolicyApplyIncomplete`, so the judgement silently retires W1's reason

`03:835` ("`incompleteOrder` gains them **at the end** … **appending leaves what those two report unchanged**") and `03:1477`, against `internal/controller/authtxn.go:366`–`:372`, `:553`–`:556`, and §3.2's reason order at `03:342`.

`incompleteOrder` is `PolicyApplyIncomplete`'s list and nothing else's. `GovernanceSkipped` has no ordering function: `reportForeign` sets it with a plain `conds.set` (`:555`), and A75 handled the collision by hand —

```go
if c, ok := conds.get(CondGovernanceSkipped); ok && c.Status == True && c.Reason == ReasonForeignTrafficPolicy {
    conds.set(CondGovernanceSkipped, True, c.Reason, c.Message+" | "+ReasonGatewayAuthPolicy+": "+msg)  // :366–:369
} else {
    conds.set(CondGovernanceSkipped, True, ReasonGatewayAuthPolicy, msg)                                // :371
}
```

— keeping the standing reason and appending its own to the message, which is §3.2's "the first is the reason, the message names every one" applied to `GovernanceSkipped`.

A80 puts `AuthPolicyNotAttached` on `GovernanceSkipped` (`03:825`, `03:1476`, §1.1's conditions row, §3.1's eight) and says nothing about that composition. Under the placement A80 specifies — after `reportForeign` **and** `reportAboveServed` — a plain `conds.set` makes the new judgement the last writer, so a served API-key Agent whose own `<agent>-auth` is not attached **beside** a foreign route-level policy, or beside a counting Gateway-level policy, reads `GovernanceSkipped=AuthPolicyNotAttached` and loses W1's `GatewayAuthPolicy` or §3.2's `ForeignTrafficPolicy` from the condition that records the tier. Both states are reachable and both already have built coverage. A80's claim "appending leaves what those two report unchanged" is true for `PolicyApplyIncomplete` and false for `GovernanceSkipped`.

**Fix.** One sentence in §3.3.3's ordering paragraph: "On `GovernanceSkipped`, which has no `incompleteOrder`, `AuthPolicyNotAttached` follows §3.2's reason order the way A75 does (`authtxn.go:366`–`:372`): a standing `ForeignTrafficPolicy` or `GatewayAuthPolicy` keeps the reason and `AuthPolicyNotAttached` is appended to the message; with neither standing it is the reason." Add the clause to §5's policy row. Add one half to case 19 (f): plant a foreign policy under a name of its own beside the not-attached `<agent>-auth`, and assert `GovernanceSkipped` reads `ForeignTrafficPolicy` with `AuthPolicyNotAttached` in its message; mutation — set `GovernanceSkipped` unconditionally, one edit, which must fail it.

### MAJOR 3 — choice A's corrected cost cell is wrong the other way: (A2′) does not close the miss, and `lastTransitionTime` is not a report clock

`03:1482` (choice A's options and cost cells).

Both corrections MAJOR 6 asked for were adopted without being re-derived, and both are false.

**(A2′) does not close the named miss.** (A2′) is "A1, plus: report the **unknown** state at once". "Unknown" in A80 is generation-relative — absent, or `observedGeneration` behind the object's. A Gateway whose controller has crashed after writing a good report at the route's **current** generation is not unknown: the report is present, at the current generation, and says `Accepted=True`. Nothing fires. (A2′) therefore detects a dead controller only once something bumps the object's generation — a promotion, a publish, a prepare — and on a stable served Agent that is never. The cell says "(A2′) closes it with no new field, no new read and no CRD change", and the recommendation says "(A2′) is the one to take if the human wants the miss closed". That steers the human to the option that does not close it.

**`lastTransitionTime` does not say when the Gateway last reported.** The cell says (A2) "needs no CRD field: the clock is already on the objects — the Gateway's own `lastTransitionTime` on the route's parent entry and on the policy's ancestor says when it last reported". It does not. Per the conditions convention that both Gateway API and this repo's own `metav1.Condition` usage follow, `lastTransitionTime` records when a condition last **changed status**, not when it was last written or last confirmed. A route accepted three weeks ago and untouched carries a three-week-old `lastTransitionTime` on a perfectly healthy Gateway. "Last report older than the window" computed from it would flag every stable route in the cluster. There is no heartbeat on a Gateway API route: `observedGeneration` is the only freshness signal, and it is generation-relative, which is why (A2) and (A2′) collapse into the same partial answer.

So the honest position is that **none of (A1), (A2′) or (A2) closes the miss in the no-write case**, and the cell currently offers the human two that claim to.

There is a fourth mechanism the table does not carry and should, because it would catch the **measured** defect directly: the assayd Gateway's own `status.listeners`. `gatewayAuthPolicies` already does a live `Get` of the Gateway on every served API-key pass (`authabove.go:204`), so for those Agents the listener status is in hand at no cost, and a `parentRef` naming the constant `http` listener that the Gateway's own status does not list is an explicit failure at the Gateway's current generation — the renamed-listener case, seen without waiting for a route-status write. A80 names "it reads no listener's own status" in "does NOT cover" (`03:1492`) but does not offer it as an option. For `auth: none` and a refused `Adopt` it would be a new read, which is the honest cost.

**Fix.** Correct the two claims in the cell: "(A2′) reports the unknown state, which closes the miss only after something bumps the object's generation — on a stable served Agent, never"; and strike the `lastTransitionTime` clause, replacing it with "there is no heartbeat on these objects: `observedGeneration` is the only freshness signal and it is generation-relative, so a window measured in the operator needs a clock the operator keeps, which is the cost (A2) carries." Add **(A4)** "read the assayd Gateway's own `status.listeners` for the listener the route names — already fetched on every served API-key pass, a new read for `auth: none` and a refused `Adopt`, and the one option that sees the measured defect without waiting for a route-status write". Then restate the recommendation against the corrected set: **(A1) plausibly still wins**, but it should win knowing that the miss it leaves is closed by none of its listed alternatives.

### MAJOR 4 — the page A80 rests its whole claim on is not built, and A80 states it in the present tense (rule 7)

`03:833` ("design 10 pages on `PolicyApplyIncomplete` open for more than 5 minutes … without the carry set this would be a log line rather than a report"), `03:1473`, `03:1343` and `03:1344` ("design 10 pages after 5 minutes"), `03:1482` ((A2′)'s "let design 10's duration threshold be the grace window").

Nothing in this repository emits that alert. `charts/assayd/templates/` contains `_helpers.tpl`, `admission.yaml`, `namespace.yaml`, `NOTES.txt`, `operator.yaml`, `pdb.yaml` and `rbac.yaml` — no alert rules, no dashboards, no OpenObserve. A case-insensitive search for "alert" across `charts/` and `config/` returns nothing. Design 10's §5 calls its rules "shipped, tunable", its own Status line says "approved", and `docs/designs/README.md:18` says "awaiting user approval" — the observability pack is P1+, and ADR-0030's scope reset is why.

This is rule 7 in its exact form: "a design table … has shipped a promise nothing implemented. If it is not enforced, say so." A80 is otherwise the most scrupulous amendment in this file about owed-and-not-built — it marks it in eight places for its own rows — and then rests its central sentence, "**which is what makes this a report rather than a log line**", on machinery that does not exist. It also matters to the decision in front of the human: (A2′)'s entire cost argument is that design 10's duration threshold serves as the grace window, and today that window is a paragraph in an unapproved design.

The debt predates A80 — §5's A75 rows already say "a page after 5 minutes" — which is precisely the shape A80 accepted for the alert's wrong parenthetical (MINOR 7): the drift is older, and A80 is the amendment leaning on it.

**Fix.** One clause where the claim is made, and the same words in §5's two new rows: "design 10 is **not built** — no alert rule ships in the chart today and its README row records it as awaiting approval — so until it does, both reasons are a condition on the Agent and nothing pages; the carry set is what makes the duration meaningful **when** design 10 lands, and the remedy is a report a human or a dashboard must read until then." Carry the same caveat into (A2′)'s cost cell, since a grace window that does not exist is not a cost saving.
