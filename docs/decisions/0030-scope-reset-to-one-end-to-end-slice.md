# ADR-0030: Narrow the delivery commitment to one end-to-end slice; the other designs become hypotheses

- **Status**: accepted · 2026-09-05 · decided by the human on the GPT-6 Astra direction review (`docs/designs/reviews/00-astra-direction-review.md`) · **Amendment 1 (2026-09-23) — the Consequences line below is corrected, not rewritten: `docs/designs/README.md` does not arbitrate design status. A design's own Status line is the source of truth, and the README summarises it. Read Amendment 1 before the Consequences.**
- **Context**: Sixteen days produced 27 designs, 12,837 lines of review — 2.9× the designs and 3× the code — and one operator. No test in this repository sends a request to an agent; the e2e runs `registry.k8s.io/pause`, `gateway.enabled` defaults to `false`, and the policy compiler does not exist, so the platform's central claim that governance becomes real at the gateway has never been exercised. Design 02 took 62 amendments without a pass and its consolidation returned 13 blockers — no Service, no rollback socket, no env injection, a credential Secret surviving deletion. Those are first-hour findings reached by cross-reading 27 documents. Meanwhile kagent v0.10.0 shipped a BYO A2A arm and ADR-0006 had already retracted the differentiator claim architecture §16 was still selling.
- **Decision**: The delivery commitment is **one end-to-end slice**: a single-team managed-container Agent, one pinned gateway release, one identity mechanism — carried until one agent completes one A2A task and one MCP tool call through the gateway, with a disallowed principal failing against a permitted control. Build order: (1) the supported slice with unsupported capabilities rejected at the boundary; (2) workload materialization — revision-scoped Services, card fetch, the runtime env contract, retained-revision selection; (3) the smallest real policy path through gateway, identity and network rules, authored by hand before it is compiled; (4) a narrow design-16 gate, blue/green before canaries; (5) one real domain on a curated knowledge snapshot; (6) a second framework, preferably a kagent BYO agent, measured against kagent plus existing delivery tooling. Designs 21, 23, 25, 26, 27 and the unimplemented parts of 11–14 and 18–19 are **demoted from approved specification to scoped hypotheses** — research retained, not prerequisites, not supported promises. Nothing implemented is deleted to reach a demo: the run namespace and immutable material stay.
- **Consequences**: "Approved" no longer means buildable — every design carries its own Status and `docs/designs/README.md` arbitrates. An unimplemented enterprise integration blocks claiming enterprise support; it does not block the slice. The first-mover framing is withdrawn (ADR-0006 already had). Stop criteria bind: if a user cannot finish the narrowed task without hand-patching status the slice is unfinished; if kagent plus an existing gate achieves the same release and recovery, prefer integration over a second platform; if the knowledge benchmark beats no simple retrieval baseline, stop expanding the ontology work. Design 03 is not resumed until the v1.4.1 spike is re-run against agentgateway v1.5.0, which added `maxConcurrentRequests` — absent in v1.4.1 — bearing directly on the unbounded-concurrency result that voided its budget ceiling.

## Amendment 1 (2026-09-23) — a design's own Status line is the source of truth; the README summarises it

**Nothing decided in this ADR is reversed, which is why this is an amendment and not a supersession.** One clause of its Consequences named the wrong authority, and the human corrected it on 2026-09-23.

The Consequences line above reads, unedited and left that way per the ADR rule:

> "Approved" no longer means buildable — every design carries its own Status and `docs/designs/README.md` arbitrates.

**The first half stands. The second is withdrawn.** A design's own Status line is the source of truth for its status, and `docs/designs/README.md` summarises it. Where the two disagree, the Status line wins, and the README row is the one to fix. `AGENTS.md` and `CLAUDE.md` already said so — "Check the Status line of the design you are about to touch, and trust that over any summary" — so this ADR and the files every contributor reads first gave opposite answers to the same question.

**Why it mattered.** Until 2026-09-23, twenty-three designs — 04–15 and 17–27 — opened their Status line with "approved", and their README rows said "awaiting user approval". The human had approved none of them. Under this ADR's wording the README won and the designs were unapproved; under `AGENTS.md`'s the Status line won and they were approved. Both rules were in force at once. The human decided three things that day:

1. **None of those designs is approved.** Their Status lines now say "not approved by the human" and keep the critique citation, the ADRs and the amendment notes they carried. Design 01's README row said "approved" while its own Status line said "revised r2"; the row is corrected.
2. **The only approvals the human has given** are design 03's first slice (2026-09-12, ADR-0034 Amendment 4), design 16's first slice (2026-09-14, ADR-0024 Amendment 1) and design 03's amendment A84 (2026-09-23). A critique PASS is not an approval.
3. **The Status line is the source of truth, and a test keeps the two in step.** `TestADesignsStatusLineAndItsIndexRowAgreeAboutApproval` in `test/docs`, run by `make docs`, fails when a design's Status line and its README row disagree about approval — whole, in part, or not at all. It compares what the two documents claim. It does not establish that the human decided anything; the ADR amendments above record that.

ADR-0026 Amendment 2 repeats the withdrawn clause ("`docs/designs/README.md` arbitrates, and a design's own Status line beats any summary"). Its second half agrees with this amendment; its first half is corrected by it. That amendment is not edited, for the same reason this body is not.

**Why this is marked here rather than fixed in place.** The `/adr` skill forbids editing an ADR's content to match a later decision: an ADR is a record of what was decided and why. This ADR is not superseded, so it gets a marker in its Status line and this amendment instead.
