# ADR-0031: Three decisions the gate surface was blocked on — resources, rollback, and where external Agents' resources live

- **Status**: accepted · 2026-09-05 · decided by the human on the GPT-6 Astra direction review; the first is implemented in this change, the other two are contracts design 02 now owes.
- **Context**: The design-02 consolidation review found three fields classified as safe live edits that can change what an evaluation gated, a retention promise with no way to request the rollback it promises, and external Agents needing gateway resources with no namespace authorized to hold them. Each had a fork a review should not pick alone.

- **Decision 1 — reject `resourceFieldRef`; keep resources live-editable; gate port and loop.** `spec.runtime.env[].valueFrom.resourceFieldRef` is refused at admission. It reads a CPU or memory limit into the container while `spec.runtime.resources` stays editable in place, so a capacity edit could change what the program reads under an unchanged revision digest — the selector is projected, the value it resolves to is not. Gating every resource edit instead would close the same hole and cost the live capacity-repair path during an OOM or throttling incident, which is worse for a first product. Separately, `runtime.port` and the whole `loop` block **move onto the behaviour surface**: one approved image may serve the evaluated A2A implementation on one port and a different handler on another, and design 22 compiles `allowReentry`/`maxVisits` into the in-proxy CEL that admits or denies each request by its lineage. Neither is capacity repair.
- **Decision 2 — rollback is a spec field, not a request CR.** Design 02 gains `spec.release.targetRevisionDigest`, selecting a retained **full digest** — unset means follow desired spec, set means stay pinned until explicitly changed or cleared. A transient request object races desired spec and is reverted by the next reconcile; a field survives GitOps, which is design 08's "every verb is sugar over CRs". A dedicated CR is justified later only if rollback needs separately delegated RBAC, approval or scheduling.
- **Decision 3 — external Agents reuse the protected run namespace, and are deferred.** When external support is built, any Agent needing protected gateway resources gets a run namespace, contributing routes and policies but no workload or env-source copies; its lifetime follows all dependent resources, not the existence of a Deployment. This reuses ADR-0029's boundary rather than inventing a policy namespace, and avoids giving a source-namespace editor control of governance objects. External Agents are **out of ADR-0030's first slice**: a remote endpoint is independently mutable, so plume cannot promise the frozen-material guarantee it gives a digest-pinned container without a further attestation contract.

- **Consequences**: The projection encoding changed — golden MIGRATION 3, and the pinned 40-bit collision pair was re-derived, which took 3.9s and is itself a restatement of why the full digest is the identity. A port or loop edit now mints a candidate and pays for a gate; that is the intended cost. `resourceFieldRef` users have no migration path and must pass the value literally — acceptable only because P1 is unshipped. Resources remain ungated, so the guarantee is narrowed rather than restated: **the gate covers named release material and capability configuration; live capacity is a documented operational exception**, and throttling or OOM can still change task outcomes. Do not cite design 20's unimplemented drift automation as its backstop. Decisions 2 and 3 are contracts, not code: design 02 §5 must list both as unavailable until they exist.
