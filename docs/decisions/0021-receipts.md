# ADR-0021: receipt/v1 — derived identity, tenant streams, tiered delivery
- **Status**: accepted · 2026-08-20 (design 04, critique PASS r2)
- **Context**: agentgateway natively exports OTLP (GenAI semconv incl. MCP spans, cost); GenAI semconv moved (June 2026) to the unreleased `semantic-conventions-genai` repo; JetStream dedup is a sliding window (~150B/entry).
- **Decision**: (1) Receipts derive from the gateway's own OTel export — tap = OTLP receiver inside the operator binary (0 pods core; `--mode receipt-tap` split at p95>250ms or >500/s; shed-telemetry-before-reconcile priority with hard caps). (2) **`receipt_id` = UUIDv5 over (trace_id, span_id)** — deterministic, so `Nats-Msg-Id` dedup works under redelivery; dedup window sized to the exporter retry horizon (default 15m ≈ 70MB at threshold), late redeliveries counted not denied: delivery = *effectively-once within a sized, alarmed horizon*, tiered core/compliance. (3) **Per-tenant RECEIPTS stream in the tenant's NATS account** (core = one account at n=1). (4) Semconv pin = commit SHA of semantic-conventions-genai (v1.41 fallback baseline), absorbed only in the transform. (5) Mandatory non-configurable credential-header scrub at every capture level, gateway-side + tap re-check. (6) Consumers split: fidelity (stream-only: eval/replay) vs aggregate (audit index; owns per-agent daily spend for the ADR-0028 backstop, staleness alarmed).
- **Consequences**: Audit integrity survives retries; interior agent spans are observability, never receipts; ADR-0003's "pin the version" reads as "pin the SHA".
