# ADR-0029: An Agent's workload and revision material live in an operator-owned namespace the operator can prove it created

- **Status**: accepted · 2026-09-04 · decided by the user 2026-08-31 (design 02 A42), made implementable by A60 (2026-09-03), implemented and proven on a real cluster the same day (A61)
- **Context**: A revision's immutable copies (A35) closed edits, not deletion: `immutable: true` forbids an update and permits delete-and-recreate under the same name, so a principal with ordinary `create`/`delete` on ConfigMaps in the Agent's namespace could still replace what a gated revision serves. A ConfigMap can only be used by Pods in its own namespace, so the material is out of that editor's reach only if the Pod is too — a namespace, not a naming scheme. Two rounds of review then showed that "created, never adopted" needs a proof a label cannot give (Codex r8 BLOCKER 7), and that the labels SPIRE and the Gateway act on must be bound to that proof or they are a convention (`reviews/02-a60-codex-review.md`).
- **Decision**: workloads, Services, routes and copies go into `plume-run-<agent-namespace>`, one per source namespace, created by the agent-operator; the Agent CR and the user's own ConfigMaps and Secrets stay where the user put them. The operator keeps a **binding record** per run namespace in its own namespace — a nonce generated before the namespace exists (defeats pre-creation) and the namespace UID recorded from the `Create` response (defeats delete-and-recreate), a strictly decoded record with a `Terminating`/`Deleting` handler for last-Agent teardown. No `ownerReference` crosses the namespace boundary; provenance is name plus UID label, and the finalizer collects. The chart reserves the `plume.dev` namespace labels to the operator's identity with a `ValidatingAdmissionPolicy`, and the operator fail-closes without it. The rejected alternative — inlining ConfigMap content into the PodSpec — left `envFrom.secretRef` exposed, and a Secret carries a system prompt as well as a key.
- **Consequences**: the operator holds cluster-wide `namespaces` create/update/delete, bounded in code by the `plume-run-` shape and the binding UID, and stated as the escalation it is (design 07 A5.7). Pod Security labels, ResourceQuota and LimitRange are mirrored, so a tenant's compute quota is a per-namespace ceiling (ADR-0026 Amendment 1). Direct `kubectl logs` in a run namespace is unsupported; `plume logs` (design 08) is the path. The SVID path segment comes from a label rather than the Pod's namespace, which moves the identity trust boundary to "who may create Pods in a `pods-by: agent-operator` namespace" — nobody but the operator, by RBAC and by the same policy. Hard mode's run namespace lives inside the vCluster (design 26 A1). `EnvSourceProtectionUnavailable` is retired. Designs: 02 §3.2/§3.5/§3.7, 07 A5, 26 A1, 03 A44/A45.
